# Cipher Engine Inventory

Phase 0 inventory for the cipher-engine verification sweep. This document records
what exists; it does not certify that an engine is correct. Correctness, robustness,
historical accuracy, and fixes belong to later phases.

## Scope and counting rule

The canonical count is the 84 properties returned by `window.CipherEngines` in
[js/ciphers/all-engines.js](../js/ciphers/all-engines.js). The generated
`all-engines.min.js` browser asset is not counted as another implementation.

Two exhibits also load dedicated implementations of algorithms that are already in
the 84-engine registry:

- Caesar loads [js/ciphers/caesar.js:6](../js/ciphers/caesar.js#L6) from
  [ciphers/caesar.html:383](../ciphers/caesar.html#L383). Its default shift is `0`,
  while the registry engine defaults to `3`.
- Enigma loads the configurable
  [js/ciphers/enigma.js:22](../js/ciphers/enigma.js#L22) and its controller from
  [ciphers/enigma.html:653](../ciphers/enigma.html#L653). This is distinct from the
  simplified registry engine. It is listed in the Enigma row rather than counted as
  engine 85.

Cryptanalysis helpers such as Caesar breaking, ELS searching, Lorenz depth attacks,
and the `solvers/` programs are outside this count because they are not exhibit
`encode`/`decode` engines.

## Evidence conventions

- **External KAT** means a fixed expected answer whose current test names an
  outside source. The per-row classifications below are the Phase 0 baseline;
  post-sweep KAT coverage is summarized after the table.
- **Local fixed** means a literal expected output or mapping exists, but its test
  does not establish independent provenance.
- **No fixed vector** means current coverage is roundtrip, involution, boundary, or
  smoke testing only.
- **Profile** links point to the per-engine entry used by the current comprehensive
  sample suite. All 84 engines have one between
  [tests/test-comprehensive.js:152](../tests/test-comprehensive.js#L152) and
  [tests/test-comprehensive.js:236](../tests/test-comprehensive.js#L236).
- Corpus counts are the `record_count` values in
  [corpus/engine-manifest.json](../corpus/engine-manifest.json). Presence does not
  mean those records have been run against the browser engine.
