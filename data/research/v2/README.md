# Research-evaluation v2

A separately versioned evaluation suite for the Evidence Workbench. **Version 1 is not
replaced.** Its fixtures, identifiers and published failures are still in
[`data/research/v1/`](../v1/README.md) and still generated by
`scripts/evaluate-research.js`. v2 adds tasks, material and controls beside them.

Generate with `node scripts/evaluate-research-v2.js`; check with `--check`. Runtime and
heap figures are machine-dependent and are excluded from that check; every other recorded
result must reproduce exactly.

## Why six tasks and not one number

These six questions are routinely reported as if they were the same question. They are not,
and a system that does well on one can be useless at another.

| Task | The question it answers |
| --- | --- |
| Independent-key recovery | One ciphertext, one key drawn for it alone. How much plaintext and key comes back? |
| Fixed-code-pool recognition | One global code pool reused across texts. Is this cryptanalysis, or recall of a map already seen? |
| Authentic known-key replay | A published key along a published route. Does the mechanism reproduce? |
| Transcription | How many glyphs are wrong, and how many are unresolved? Reported apart from plaintext error. |
| Numerical segmentation | Where do the boundaries fall, and how many readings survive? Boundary error is not plaintext error. |
| Language and historical-domain shift | Which language profile fits, and when should the comparison decline to choose? |

## Split and grouping rules, audited on every run

Declared in [`scripts/research-splits.js`](../../../scripts/research-splits.js) and checked
by `tests/test-research-evaluation-v2.js`, which asserts that the rules actually reject the
leakage they describe:

- **Source grouping.** Every ciphertext variant derived from one source plaintext stays in
  one split. Variants of one text are not independent items.
- **Disjoint key seeds.** Each split draws key seeds from its own numeric range, so a seed
  can never appear on both sides.
- **Disjoint code pools.** The fixed-pool task draws its pools from per-split ranges. A pool
  shared across splits would turn recognition into memorization.
- **Collection-level assignment.** Splits are assigned per collection, so a whole body of
  material can be held out.

The only `development` collection is the set of probes the language-profile abstention
thresholds were calibrated on. Nothing else was tuned against anything.

## Material and rights

- **Museum-authored prose** (`data/research/v2/corpus.json`): original English and French
  written for this repository. `letter-a`, `letter-b` and `language-shift` are the v1
  fixtures, retained so their failures remain the baseline; `letter-c` is new in v2.
- **Held-out historical passages** (`data/research/v2/holdout.json`): extracts from the
  pre-1800 public-domain works used to build the language profiles, reserved *before*
  counting so the model has not seen them. Same works and same authors — a document-internal
  holdout, **not** an independent source document.
- **Authentic Z340 first section** (`data/research/v1/z340-section-1.json`), unchanged.

**None of this is a blind benchmark.** Every fixture, key and seed is visible in a public
repository, and renaming a file does not change that.

## Measured results

39 items at the published budget (seed 41, 6,000 annealing steps, beam width 150, 26-way
branching), 13 source documents, all in the `test` split.

### Independent-key recovery — both solvers fail, and that is the result

| Solver | Mean plaintext error | Mean key error | Exact recoveries | Mean runtime |
| --- | --- | --- | --- | --- |
| Simulated annealing | **74.9%** (41.9–83.3%) | 91.3% | **0 of 39** | 60 ms |
| Beam search | **79.1%** (62.5–83.7%) | 93.2% | **0 of 39** | 1,256 ms |

Beam search is both worse and about twenty times slower here. It is retained as a
comparison baseline, not as an improvement. Under identical inputs, language resources and
assistance, **neither solver recovered any of these texts.** The published v1 numbers
(33.2%, 46.0% and 73.3% on longer texts at a 15,000-step budget) remain the baseline and
are not superseded by these.

Two invariants hold for both solvers on all 39 items: applying the complete known key is
**exact 39 of 39**, and relabelling every symbol leaves the search outcome unchanged.

### Fixed-code-pool recognition — a different task

Applying a code pool already held: **exact on 13 of 13**. Recovering the same pool from one
short text: **72.8% mean plaintext error**, 87.4% key error, with each text exercising on
average 75.7% of the pool's symbols. A method trained on a shared pool is being measured on
recall, not on independent cryptanalysis.

### Numerical segmentation — verified against an exhaustive oracle

All five single-line cases match an independent exhaustive enumeration, and the three with
a hand-computed expected answer match that too. Ambiguous `2228` yields `AAAD`, `AND`,
`NAD`; one locked boundary removes `NAD`; a key missing a needed code yields nothing and
says so. Null codes, multi-reading word codes and line boundaries are carried as typed
entries, and line breaks are mandatory cuts that no code may span.

Boundary error is reported apart from plaintext error: reading `2|22|8` as `22|2|8` moves
**one** boundary and changes **two of three** letters.

Twenty repeated digits under `{2, 22}` admit 10,946 complete paths. At a 1,000-node budget
the lattice falls back to bounded k-best, retains 32, and reports
`globalBestGuaranteed: false` with the reason. **Pruning removes the guarantee, and the
result says so rather than implying a best answer.**

### Language and historical-domain shift

All **9 of 9** held-out passages were decided, and all 9 correctly, three per profile. All
three controls behaved correctly: English — which has no profile — was **abstained on**;
museum-written modern French ranked the French profile first, which is right about the
language and silent about the period; random letters were abstained on.

Nine passages from three works is a small measurement, and the passages share authors and
works with the training material. It shows the comparison and its abstention rule function;
it is not a language-identification accuracy figure.

**Unresolved coverage:** German, Spanish, English and every other language in the historical
record have no profile. A text in one of them can only be abstained on or mis-assigned.

## Limits

- Held-out passages are not independent source documents.
- Budgets are small enough to run in the test suite on every change. A larger budget is a
  separate experiment; it would not change which task is which.
- Runtime and heap figures are Node.js measurements around single calls, not peak resident size.
- A score is never a probability that a reading is historically correct.
