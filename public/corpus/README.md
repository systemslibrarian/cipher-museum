# Cipher Corpus

Cipher Corpus is an educational benchmark library for classical cryptanalysis. It is not a collection of secrets and not a production cryptography resource.

Known answers are the point. Learners can hide the solution in Challenge Mode, while tools can use the answer metadata for scoring.

## What is Cipher Corpus?
A curated library of ciphertext challenges, known plaintexts, keys, and metadata for learning, teaching, scoring, and benchmarking classical cryptanalysis.

## Intended Uses
- Practice codebreaking and cryptanalysis
- Benchmark classical cipher solvers
- Educational activities for students and tool builders

## Terminology
- "Known-ciphertext" means the museum provides ciphertext challenges with known answers for scoring and education.
- "Challenge Mode" hides the solution for learners.
- "Known Corpus Mode" reveals the answer for benchmarking and tool building.

## Data Fields
See `cipher-corpus.schema.json` for all required fields and types.

## File Formats
- JSONL: One JSON object per line (recommended for tool builders)
- JSON: Array of records
- CSV: Tabular data

## Licensing
All synthetic records are CC0. Historical records include per-record license.

## Limitations
Cipher Corpus v0.1 begins with synthetic benchmark examples. Synthetic records are useful for controlled testing but are not a substitute for historical cipher archives.

## How to Contribute
Submit records with plaintext, ciphertext, cipher type, key/settings, source, license, verification status, expected attacks, and difficulty suggestion. Historical submissions must include source and rights information.

## Synthetic vs Historical
Synthetic records are generated by Cipher Museum or from public domain sources. Historical records are labeled and sourced.

## Why Known Answers?
Known answers allow for scoring, benchmarking, and educational use. Hide solutions in Challenge Mode for practice.

## Quality and Validation Rules
All Cipher Corpus records must:
- Include both plaintext and ciphertext, with the key/settings required to reproduce the encryption.
- Specify the cipher family and cipher type (e.g., substitution, Vigenère, Playfair, etc.).
- Clearly state the language, alphabet, and casing used.
- Specify spacing and punctuation handling (preserved, removed, grouped, or mixed).
- Assign a difficulty level (beginner, intermediate, advanced, expert).
- Include expected attack methods (e.g., frequency analysis, Kasiski, crib dragging, etc.).
- Include a source type (synthetic, historical, public_domain, user_contributed) and a source reference.
- Include a license (CC0 for synthetic, or appropriate for historical/public domain).
- Be reproducible: ciphertext must match the plaintext, key, and settings.
- Pass schema validation (see cipher-corpus.schema.json).
- Be labeled as verified only if independently checked for correctness.
- Label synthetic and user-contributed records clearly; historical records must include provenance and rights.

Validation is enforced via JSON Schema (cipher-corpus.schema.json) and automated test scripts. Submissions failing validation will not be included in official releases.
