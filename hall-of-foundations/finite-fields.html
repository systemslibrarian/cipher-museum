The Arithmetic World Everything Happens In

When the curve
shatters

The elliptic curve you saw drawn as a smooth loop doesn't live on paper when it does real work. It lives over a finite field — a world with only finitely many numbers, where the curve becomes a scatter of dots. Suitable large finite-field groups can support hard discrete-log problems; the tiny groups here do not.

Arithmetic, not a security test. The real and finite-field pictures use related formulas, but apparent visual disorder does not prove discrete-log hardness. Curve choice, subgroup order, validation and implementation all matter.
§1

A field with no infinity

A finite field 𝔽ₚ is arithmetic modulo a prime p: the only numbers are 0, 1, …, p−1, and everything wraps around. Add, subtract, multiply, and — crucially — divide, all staying inside that finite set. Every nonzero element has an inverse, which is what makes it a field rather than just a ring.

𝔽ₚ = { 0, 1, 2, …, p−1 }  with arithmetic mod p

The same elliptic-curve equation, y² = x³ + ax + b, now asks which pairs (x, y) satisfy it modulo the prime. The group also includes an identity called the point at infinity; that identity is not an extra field element.

§2

The curve, over 𝔽ₚ

Below is y² = x³ + 2x + 2 over 𝔽ₚ. Change p and watch the point set redraw. Notice the vertical symmetry — for every point (x, y) there's a mirror (x, p−y) — the finite-field ghost of the real curve's reflection.

—
Every dot is a genuine solution of y² ≡ x³ + 2x + 2 (mod p), computed exactly. The count is the order of the curve — the size of the group your key lives in.
§3

Adding points in the dark

The chord-and-tangent rule still works — but algebraically, not geometrically. Pick a starting point G and repeatedly add it to itself. Over the reals you could watch it slide along the curve. Here it jumps. Press step and follow G, 2G, 3G… as they scatter with no visible pattern.

k = 0
You can see k and where kG landed. The discrete log problem is the reverse: given only the landing spot, recover k. This tiny group is easy to search; the plot alone tells us nothing about cryptographic hardness.
Forward scalar multiplication is efficient. Generic reverse attacks take roughly the square root of the subgroup order, with special curves permitting faster attacks. That distinction is one algebraic ingredient in a secure protocol.
§4

Four different promises about the same addition

The arithmetic above is correct and it is also a teaching model. Production elliptic-curve code carries claims this exhibit does not, and the claims are not interchangeable. Four of them are worth separating.

What each assurance covers, and what it leaves open
ClaimWhat it meansWhat it does not cover
Exceptional cases handledThe affine chord-and-tangent rule has no slope when the two points share an x-coordinate, so an implementation must branch: identity, inverse pair, doubling, general case.Branching is where bugs and timing differences live. Handling a case is not handling it in constant time.
Complete addition formulasOne branch-free expression that is correct for every pair of points, including the identity and a point with itself. Renes, Costello and Batina give such formulas for short Weierstrass curves.The completeness guarantee holds for a stated curve class — prime-order short Weierstrass curves over fields of characteristic other than 2 and 3. Outside that class the guarantee does not transfer, and the formulas cost more field multiplications.
Functional-correctness proofA machine-checked argument that a particular implementation computes the specified mathematical function, including the bounds that keep intermediate values in range. Fiat-Cryptography produces field arithmetic this way.A proof has a boundary. The compiler, the pretty-printer and anything below them are trusted, not proved, and the proof says nothing about timing.
Constant-time assuranceThat the execution time and memory-access pattern do not depend on secret values.This is a property of the emitted machine code. A compiler is free to introduce a branch or a table lookup that the source did not have, so the assurance has to be re-established after compilation.

Where that leaves the code on this page. The museum’s ec-math.js is affine, branching, and uses a linear search to invert a field element because the fields here have fewer than a hundred elements. It is not production-ready, not constant-time, and not formally verified, and it is not trying to be. What it is is checked: the museum’s test suite compares its result against an independent implementation of the complete projective formulas on all 361 ordered pairs of points on the prime-order curve y² = x³ + 2x + 2 over 𝔽₁₇, identity, inverses and doublings included. Agreement on a tiny curve is evidence about these formulas on this curve; it is not an assurance claim about anything else.

Property testing, proof and timing assurance answer different questions, and passing one says nothing about the others. For side-channel behaviour as a measured phenomenon rather than a source-code property, see what a power-analysis result actually shows and Crypto Lab’s Power Trace, which computes those statistics over simulated leakage.

Joost Renes, Craig Costello and Lejla Batina, “Complete Addition Formulas for Prime Order Elliptic Curves,” EUROCRYPT 2016: the curve class the completeness guarantee is stated for, and its cost. Andres Erbsen, Jade Philipoom, Jason Gross, Robert Sloan and Adam Chlipala, “Simple High-Level Code for Cryptographic Arithmetic — With Proofs, Without Compromises,” IEEE S&P 2019: the proof pipeline, its bounds reasoning, and the trusted compiler and pretty-printer at its edge.

Where this touches your keys

This is the ground floor of ECC

Real elliptic-curve cryptography uses carefully selected large fields, curves and prime-order subgroups. For common 256-bit prime-order groups, generic discrete-log attacks take roughly the square root of the group order, not a search through every field element. These tiny plots are readily enumerable and demonstrate arithmetic, not security.

AES uses a finite field too, but a different kind of one, and the distinction is worth drawing. This exhibit builds GF(p) — arithmetic modulo a prime. The AES S-box lives in GF(2⁸), an extension field of 256 elements whose members are polynomials, added bitwise and multiplied modulo a fixed irreducible polynomial. Same guarantee — every nonzero element has an inverse — reached by different construction, and the S-box maps zero to zero for the inversion step, takes the multiplicative inverse for every nonzero input, and then applies an affine map. The polynomial machinery is next door in Polynomial Rings.

Companion: The Ground Beneath the Curve shows the smooth real-number version and the deep theory of why these curves are so well-behaved.
