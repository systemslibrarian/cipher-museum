### What an Attack Result Actually Shows

Compare the access, data, computation and validation behind modern cryptanalytic results.

#### Keep five quantities separate

A useful attack card identifies the target configuration, attacker access, data requirement, computational work and success criterion. A measured throughput is not an observed full-key recovery, and a theoretical keyspace is not necessarily the effective keyspace of a deployment.

#### GPU search: which keyspace?

The 2025 ToSC paper “GPU Assisted Brute Force Cryptanalysis of GPRS, GSM, RFID, and TETRA” compares optimized implementations and time–memory trade-offs. Its KASUMI-64 setting uses a repeated 64-bit key in a 128-bit-key primitive. That deployment is not equivalent to searching all independent 128-bit KASUMI keys.

The paper’s TETRA target here is **TEA3, not TEA1**. Its extrapolated SPECK-96 and TEA3 exhaustive-search costs remain enormous. Reporting fast GPU throughput as a practical break of every listed cipher would erase the paper’s distinctions.

Separate measured RTX 4090 throughput from extrapolated total search time, preprocessing, memory, and probability of success. Hardware and cost assumptions are dated measurements, not current cloud-price quotes.

[Primary journal paper (2025)](<https://doi.org/10.46586/tosc.v2025.i1.309-327>) · [Institutional full text](<https://research.sabanciuniv.edu/id/eprint/51583/1/GPU%20Assisted.pdf>), PDF pp. 1–3 and 12–15. Compare [DES’s finite keyspace](<https://ciphermuseum.com/ciphers/des.html>) and [SoDark’s related-tweak attacks](<https://ciphermuseum.com/ciphers/sodark.html>).

#### Power observation: a model of the implementation

A passive power attack observes executions; active fault injection tries to alter them. In correlation power analysis, an analyst selects a key-dependent intermediate, predicts it under small subkey hypotheses, models its leakage, and compares those predictions with associated power traces.

This needs repeated executions under the relevant key, known associated inputs that vary, aligned traces or a way to align them, an appropriate leakage model, and sufficient signal relative to noise. Hamming weight HW counts one-bits in a value. Hamming distance models a transition: `HD(a,b) = HW(a XOR b)`. Neither model is an exact law for every device’s consumption.

A high correlation or candidate rank is evidence to test, not recovery confirmed against a known answer. Noise, mismatched models and acquisition conditions affect the result; there is no universal trace count or recovery time. A physical implementation can leak without a mathematical break of AES.

[Power Trace](<https://systemslibrarian.github.io/crypto-lab-power-trace/>) computes CPA/DPA statistics over **simulated leakage**; those results are not measured-device evidence. For the effect of combining masked observations, see the [Museum’s exact masking example](<https://ciphermuseum.com/ciphers/aes.html#masking>) and [Masked Core](<https://systemslibrarian.github.io/crypto-lab-masked-core/>).

Stefan Mangard, Elisabeth Oswald and Thomas Popp, *Power Analysis Attacks: Revealing the Secrets of Smart Cards* (2007), introduction, pp. 1–13; §3.3, pp. 38–42; §§6.1–6.2, pp. 119–124. These implementation conditions differ from the [induced-fault model below](<https://ciphermuseum.com/lab/modern-attack-evidence.html#faults>).

#### GPRS faults: physical access changes the model

“Practical Differential Fault Attacks on the GPRS Standard Ciphers” analyses GEA-1 and GEA-2 under the **random fault model**: the attacker may induce faults into the internal state bits but does not know the exact location at the moment of injection. The authors implemented both ciphers on a **ChipWhisperer Lite** board with an XMEGA target, injected faults by **voltage glitches**, and ran the whole attack there. That is evidence about a cipher running on an instrumented board the attacker controls.

**The two capabilities the attack assumes.** The paper states its model as (a) the attacker can reinitialize the encryption operation repeatedly *with the same key–IV pair*, and (b) the attacker can flip a state bit without knowing which one. Both fault-free and faulty **keystream** must be readable, because the keystream is what filters out wrong internal-state guesses; the attacks use 2,048 keystream bits, well inside GEA’s 12,800-bit frame limit. The authors say plainly that such an adversary “is certainly more powerful than a normal passive attacker and has the ability to access the keystream generator as a physical device.”

**Locating the fault is a separate problem from recovering the state.** Because the location is random, the attack runs in two processes: a dedicated algorithm identifies the exact fault location, and only then is the internal state reconstructed. The paper measures those phases apart. Fault acquisition and location is bench work on the board; state recovery is computation afterwards on a 1.19 GHz Intel Core i5-1035G1 laptop.

Reported experimental timings — one platform, one implementation

| Cipher | Executions | Fault injection and location | Internal-state recovery | Reported total |
| --- | --- | --- | --- | --- |
| GEA-1 (96-bit state) | 64 | 343.330 s average | 308.868 s | 652.198 s ≈ 10.870 min |
| GEA-2 (125-bit state) | 32 | 587.625 s average | 320.473 s | 908.098 s ≈ 15.135 min |

Both rows sum exactly, and 908.098 s is the figure behind the abstract’s “within sixteen minutes.” The GEA-1 recovery time is itself a sum: about 46.414 s, 82.323 s and 180.131 s for registers A, B and C. Separately, the paper gives *analytical* time complexities of 2<sup>33.807</sup> and 2<sup>33.858</sup> for recovering each 64-bit key. A wall-clock measurement on one laptop and an operation count are different quantities; neither is a guarantee.

**Three success probabilities, three different questions.** Table II reports about **0.995** for one thing only: the probability that the fault-location algorithm identifies the *exact* location, once at least 2,048 keystream bits are available. The attack’s modelled success is then built from it. For GEA-1 the paper computes p ≈ p₄ · (0.995)² = **0.953** of recovering the full 96-bit internal state; for GEA-2, p ≈ q₆ · (0.995)³ = **0.893** of recovering the full 125-bit internal state. Quoting 0.995 or 0.893 as “the chance of breaking GPRS” merges a sub-step, a per-cipher state-recovery model, and an operational claim that the paper never makes.

**What this is not.** The experiment does not demonstrate passive interception of arbitrary commercial phones. It does not show that the required bit flips can be induced in a deployed handset, that an eavesdropper without the device can reach the internal state, or that same-key–IV re-initialization on demand is available to a remote attacker. A result obtained by glitching a board you hold is a statement about the cipher’s fault resistance, not about the radio link. The paper’s own framing of why the ciphers still matter — ETSI prohibited GEA-1 in phones from 2013 but tested handsets were found still supporting it, and GEA-2 remains in use — is a deployment argument, separate from what the fault experiment measured.

**GEA-2M is a proposal, not a standard.** The authors propose a modified GEA-2 in which the filter function’s output bits are XORed back onto the four registers’ feedback, turning the LFSRs into mutually dependent NFSRs so that signature vectors — and therefore the fault-location step — cannot be constructed. They also discuss generic countermeasures such as double modular redundancy. GEA-2M is a research countermeasure put forward in this paper; it is not standardized, deployed, or independently evaluated.

Compare the need for controlled physical faults with the data/oracle access in [SoDark](<https://ciphermuseum.com/ciphers/sodark.html>) and the authentication/configuration conditions in [NFC](<https://ciphermuseum.com/ciphers/nfc-deployment.html>). The point of the comparison is to ask what an attacker must actually be able to do.

Zhengting Li, Lin Ding, An Wang, Haotong Xu, Zheng Liu, Zheng Wu, Xinhai Wang and Jiang Wan, [IEEE Transactions on Dependable and Secure Computing 23(3), pp. 7129–7142 (2026)](<https://doi.org/10.1109/TDSC.2026.3671957>); [ePrint 2026/1806](<https://eprint.iacr.org/2026/1806>) is a minor revision of that published work, and the [authors’ institutional record](<https://pure.bit.edu.cn/en/publications/practical-differential-fault-attacks-on-the-gprs-standard-ciphers/>) confirms the journal article. Figures above read from §§I–III and IV.C–D, V.A–D and VI, PDF pp. 1–2, 4–5 and 9–12: attack model p. 5, GEA-1 timings p. 9, Table II and GEA-2 timings p. 10, GEA-2M pp. 11–12. Phase sums and the minute conversions were recomputed here.

#### Historic full-DES differential attack: collection is not analysis

Biham and Shamir’s attack targets all 16 rounds with the standard DES key schedule. Its chosen-plaintext form requires access to encrypt structured inputs with the needed XOR differences. Table 5.2 of their book separates these rounded resource estimates:

Historical estimates, not a modern hardware benchmark

| Resource | Approximate amount |
| --- | --- |
| Chosen plaintexts collected | 2<sup>47</sup> blocks |
| Retained data analyzed | 2<sup>36</sup> blocks from that collection |
| Analysis work | 2<sup>37</sup> equivalent DES operations, excluding collection |
| Separate known-plaintext variant | 2<sup>55</sup> known plaintexts |

Possessing 2<sup>36</sup> arbitrary ciphertexts does not supply the selected data. Nor is 2<sup>37</sup> the total end-to-end work. The more precise metastructure estimates in §5.1 are 2<sup>47.2</sup> chosen plaintexts and 2<sup>37.2</sup> analysis operations.

Success is probabilistic. The book’s base schedule uses about 2<sup>35</sup> structures of 2<sup>13</sup> inputs (2<sup>48</sup> plaintexts) and gives about a 58% chance of at least one right pair. Metastructures obtain four times as many pairs from twice as many inputs, reducing the rounded collection requirement to 2<sup>47</sup>. The 58% figure describes that base schedule; it is not an exact success guarantee for every rounded estimate. Restricted input alphabets also matter: the original differences cannot be realized using only ASCII inputs; the book’s adapted attack needs about 2<sup>49</sup> chosen ASCII plaintexts.

[Start with the DES S1 worked example](<https://ciphermuseum.com/ciphers/des.html#s1-differential>) or explore differential methods in [Biham Lens](<https://systemslibrarian.github.io/crypto-lab-biham-lens/>). Those bounded exercises do not execute this full-DES attack.

Eli Biham and Adi Shamir, *Differential Cryptanalysis of the Data Encryption Standard* (1993), chapter 5 and §5.1, Table 5.2. Numbered pp. 78–86, especially pp. 84–86, refer to the authors’ repaginated 7 December 2009 recompilation.

#### Conditional-linear DES: discard data to gain bias

Biham and Perle’s 2018 conditional-linear analysis conditions linear approximations on observable information. Keeping a selected subset can increase statistical bias, trading discarded data against a stronger distinguisher.

One reported full-DES operating point uses about 2<sup>41.9</sup> known plaintexts and analysis work at 85% success. These are separate quantities even when their exponents coincide. The paper includes statistical/reduced-round experiments and selected full-DES checks; §4.7 counts the candidate keys preceding the correct key instead of executing that search; §4.7.1 reports 79 full-DES data/analysis runs using this distinction. It is not a guaranteed, ciphertext-only or laptop-speed recovery claim.

This is **conditional-linear** analysis. Crypto Lab’s [Matsui Line differential–linear composition lesson](<https://systemslibrarian.github.io/crypto-lab-matsui-line/>) is a different technique. The museum’s contribution is a dated explanation of the result and its evidence conditions.

[Biham and Perle, primary ToSC paper (2018)](<https://doi.org/10.46586/tosc.v2018.i3.215-264>), Tables 1–2 and §4.7–4.7.1, PDF pp. 5–6 and 30–34. [Journal full text](<https://tosc.iacr.org/index.php/ToSC/article/download/7302/6476>). [Return to the DES exhibit](<https://ciphermuseum.com/ciphers/des.html>).

#### Four more results, read the same way

Each card below answers the same six questions: **what version, when, what access, what special assumptions, what resources, and what was actually recovered.** These are historical findings about specific tested releases. None is a current product advisory, and none is reproduced here as a simulator — where the museum already explains the underlying mechanism, the card links to it.

##### Juniper Dual EC: the backdoor was a constant

Target and date

Juniper NetScreen devices running ScreenOS. The enabling changes shipped in a single 2008 release (6.2); the substituted constant was introduced between 6.2.0r14 and 6.2.0r15 in 2012; Juniper announced it on 17 December 2015 (CVE-2015-7756, “VPN Decryption”) and patched in April 2016.

Access

**Passive.** Observing one IKE handshake is enough — the analysis shows it is possible “to passively decrypt an individual VPN session in isolation without observing any other network traffic.”

Special assumptions

The attacker must know the discrete logarithm of the substituted Dual EC point *Q*. Three ScreenOS choices made that sufficient: Dual EC emits only 30 of a point’s 32 bytes; ScreenOS’s IKE nonce was enlarged to 32 bytes, assembled from one 30-byte output plus 2 bytes of the next, which narrows candidate states to typically one to three; and the ANSI X9.31 layer that was supposed to filter the output **never runs** — `prng_reseed()` sets the global output index to 32, and the loop that would invoke X9.31 uses that same global as its counter, so it executes zero iterations.

Resources

Negligible once *d* is known. Demonstrated as a proof of concept against an SSG-550M running ScreenOS 6.3.0 with a *Q* of the researchers’ choosing.

Recovered

The PRNG state, hence the IKE Diffie–Hellman private share, hence the VPN session keys.

Limits

**Cryptanalysis does not settle attribution.** The paper establishes what the code does and that a third party changed *Q*; it says knowing that “is suggestive — but not dispositive,” and explicitly sets aside questions of motive and identity as requiring “a different body of material.” Juniper’s own 2008 constants were never verifiably shown to have unknown discrete logs. Juniper also noted there is no way to detect whether the vulnerability was exploited.

Stephen Checkoway, Jacob Maskiewicz, Christina Garman, Joshua Fried, Shaanan Cohney, Matthew Green, Nadia Heninger, Ralf-Philipp Weinmann, Eric Rescorla and Hovav Shacham, [“A Systematic Analysis of the Juniper Dual EC Incident,” CCS 2016](<https://doi.org/10.1145/2976749.2978395>) ([ePrint 2016/376](<https://eprint.iacr.org/2016/376>)), abstract and §§3–5.3, PDF pp. 1–5. Compare a backdoor delivered as firmware rather than a constant: [UA-8295](<https://ciphermuseum.com/ciphers/ua-8295.html>).

##### Word and Excel: the same keystream, twice

Target and date

RC4 document encryption in Microsoft Word and Excel, reported January 2005; the analysis uses **Word 2002** to illustrate and names Office 97, 2000 and 2003 Word and Excel as affected.

Access

**Passive**, but the attacker needs *two or more saved versions* of the same password-protected document.

Special assumptions

The encrypted document is modified and saved again under the same password *and the initialization vector does not change*, so RC4 produces the same keystream for both versions.

Resources

Trivial. The work is reading a two-time pad, not searching a key space.

Recovered

Document content, wherever the two versions differ — not the password and not the RC4 key.

Limits

A twenty-year-old finding about a superseded format. Modern Office formats use different encryption, and this card is not a statement about any current release. What transfers is the principle, not the advisory.

Hongjun Wu, [“The Misuse of RC4 in Microsoft Word and Excel,” ePrint 2005/007](<https://eprint.iacr.org/2005/007>) (11 January 2005), abstract and §§1–3. This is the same depth problem the Allies exploited on [Lorenz](<https://ciphermuseum.com/ciphers/lorenz.html>), where two messages sent on one wheel setting opened the traffic; see also [why a pad must be used once](<https://ciphermuseum.com/ciphers/one-time-pad.html>).

##### KASUMI: four related keys, not one phone call

Target and date

The full 8-round KASUMI block cipher underlying A5/3 in third-generation GSM, 2010.

Access

**Related-key.** The attack needs encryptions under **four keys with a chosen relationship** to the unknown key. A passive listener to an ordinary call has no way to obtain these.

Special assumptions

A “sandwich” distinguisher covering 7 of 8 rounds with probability 2⁻¹⁴, available only in the related-key model.

Resources

2²⁶ data, 2³⁰ bytes of memory, 2³² time. The authors simulated the attack in under two hours on a single PC.

Recovered

The complete 128-bit KASUMI key — *within that model*.

Limits

**This does not passively decrypt ordinary calls.** It is also specific to KASUMI: the authors state that neither their technique nor any other published attack breaks MISTY, the cipher KASUMI was derived from, in less than 2¹²⁸ work. The simplifications made to MISTY for hardware efficiency are what the attack exploits.

Orr Dunkelman, Nathan Keller and Adi Shamir, [“A Practical-Time Attack on the A5/3 Cryptosystem Used in Third Generation GSM Telephony,” ePrint 2010/013](<https://eprint.iacr.org/2010/013>), abstract. For a different question about KASUMI’s deployed key, see the [GPU search card above](<https://ciphermuseum.com/lab/modern-attack-evidence.html#gpu>): a repeated 64-bit key is not an independent 128-bit key.

##### Bluetooth pairing: changing a coordinate nobody checks

Target and date

Bluetooth Secure Simple Pairing’s authenticated elliptic-curve Diffie–Hellman, disclosed 2018 and published at SAC 2019.

Access

**Active** man-in-the-middle, present during pairing, in radio range of both devices.

Special assumptions

Both devices must fail to validate that a received public key lies on the curve. The standard transmits both coordinates but the user-checked numeric comparison covers only *x*, so the attacker can silently replace *y*. Setting *y* = 0 produces a point of order 2, leaving only two possible shared secrets, both known to the attacker.

Resources

Negligible computation; the cost is the radio position and timing.

Recovered

The session encryption key, in about **50%** of pairing attempts; the other half simply fail to pair. **Not** a long-term private key — unlike the classical invalid-curve attack, this one deduces the shared secret rather than extracting the victim’s private scalar.

Limits

Affected vendors patched, and the specification was amended to require public-key validation. Treat this as a worked example of what unvalidated inputs cost, not as a live advisory about current devices.

Eli Biham and Lior Neumann, [“Breaking the Bluetooth Pairing — The Fixed Coordinate Invalid Curve Attack,” SAC 2019](<https://eprint.iacr.org/2019/1043>), abstract and §§1–4. The group law being abused is the one built in [Elliptic Curves](<https://ciphermuseum.com/hall-of-foundations/elliptic-curves-real.html>) and moved to a finite field in [Finite Fields](<https://ciphermuseum.com/hall-of-foundations/finite-fields.html>).

##### Confinement is not key recovery

These two Diffie–Hellman failures are routinely merged, and they should not be. **Small-subgroup confinement** means an active attacker sends a key-exchange value of small order, forcing the shared secret into a tiny set the attacker can enumerate. That compromises the session and can leak a few bits of the victim’s exponent. **Static private-key recovery** is a different, much stronger outcome: it needs the victim to reuse one exponent across many such queries, so that the leaked residues can be combined.

The 2016 measurement study found that of more than twenty open-source cryptographic libraries and applications examined, *none* validated subgroup orders by default before January 2016, and that millions of hosts use DSA and other non-“safe” primes. Feasible full or partial key recovery was found in specific applications — OpenSSL, Exim, Unbound and Amazon’s load balancer — with weaker attacks applicable far more widely. The distinction the paper draws is exactly the one to keep: a validation failure is near-universal; a full static-key recovery needed particular reuse conditions in particular software.

Luke Valenta, David Adrian, Antonio Sanso, Shaanan Cohney, Joshua Fried, Marcella Hastings, J. Alex Halderman and Nadia Heninger, [“Measuring small subgroup attacks against Diffie-Hellman,” ePrint 2016/995](<https://eprint.iacr.org/2016/995>) (NDSS 2017), abstract. The exchange itself is explained in the [Diffie–Hellman exhibit](<https://ciphermuseum.com/ciphers/diffie-hellman.html>); the same exhibit’s security panel covers the related question of shared primes, precomputation and the 2015 Logjam downgrade.

#### What an AI cipher result actually tested

“A model got 85% on ciphers” is four different claims wearing one sentence. Separating them is the whole job, and the separation is not pedantry: the four sit at wildly different distances from reading a message.

Four tasks, in increasing order of what they would actually demonstrate

| Task | What the system is given | What a high score shows |
| --- | --- | --- |
| **Metadata recognition** | A filename, a header, a dataset label — anything beside the ciphertext | That the label was readable. Nothing about the ciphertext. |
| **Cipher-family classification** | Ciphertext only; answer is a family or mode | That the output carries a statistical signature. The message stays unread. |
| **Fixed-codebook recognition** | Ciphertext drawn from a code pool the system was trained on | That a mapping already seen can be reapplied. Not recovery of an unseen key. |
| **Plaintext or key recovery** | Ciphertext under a key generated for that message alone | Decipherment. This is the hard one, and it is the one most rarely measured. |

**The metadata gap is measurable, and it is large.** The ACTS benchmark removes metadata in tiers — full metadata, filename only, completely blind — and reports the drop directly: combined accuracy falls from **71.7% with metadata to 30.8% blind**, a gap of 40.9 points, on live API inference over a corpus with randomized padding. Whatever the blind number means, the difference between the two is a measurement of how much of the original score was the filename.

**A deterministic substitute is not a model.** ACTS is explicit that its forced-reasoning tier is executed by *deterministic heuristic substitution rather than live API calls*. That design answers a real question — whether a prompt format changes classification under otherwise fixed conditions — but it cannot establish what reasoning prompts do to a live model, because no live model ran. A perturbation that leaves a content-blind heuristic unchanged is not evidence of semantic robustness; a content-blind procedure was never going to move.

**Classification is not recovery, and it degrades off-domain.** Work on cipher identification by randomness fingerprints reports AUC above 0.98 on the Canterbury Corpus and, more usefully, reports what happens when the plaintext distribution shifts: baseline classifiers degrade sharply as structured plaintext thins out, while the fingerprint method holds above 0.90 even on purely random data. The honest reading is that identification can be robust and still be identification — a strong AUC for telling ciphers apart is not a break of any of them, and says nothing about a single plaintext letter.

**A shared code pool changes the task.** An attention-augmented LSTM reports near-perfect character-level accuracy on synthetic historical homophonic ciphertext, and states the setting plainly: “all ciphertexts draw from the same known homophonic code pool, while individual keys use different consistent subsets of that pool.” That is a deliberate, historically motivated choice for cases where key reuse is suspected — and it is structurally a different problem from recovering a key drawn for one message. The museum’s own [research-evaluation v2](<https://ciphermuseum.com/data/research/v2/README.md>) measures both and gets opposite answers: applying a held pool is exact 13 of 13, while recovering the same pool from one short text leaves 72.8% mean plaintext error.

##### A matched-input recipe you can actually run

This is a **reproducible procedure, not a result**. The museum has not executed it, and no numbers from it are published here. Run it yourself and the claim you end up with will be about your model, on your date, under your settings.

- **Build matched pairs.** The same ciphertexts twice: once with filenames, headers and dataset labels intact, once with every one of them stripped or randomized. Identical bytes of ciphertext in both arms.

- **Fix the inference procedure.** One model version, one temperature, one prompt template, one date, one maximum token count, recorded. A changed model version invalidates the comparison as surely as a changed prompt.

- **Add two floors.** A *label-shuffled* baseline, where the answer key is permuted, shows what the scoring itself yields by chance. A *length-only* baseline, predicting from ciphertext length alone, shows how much is carried by a feature that has nothing to do with content. A result not clearly above both floors has not shown anything.

- **Report each task on its own line.** Family classification, codebook recognition and plaintext recovery get separate denominators and separate numbers. Never one combined figure.

- **Disclose what actually ran.** State for every tier whether a live model was called or a deterministic procedure stood in for it. If no model ran, the result is about the procedure.

##### Reading someone else’s benchmark

Six questions, in the order they usually need asking. *Was metadata present?* *Which of the four tasks above was scored?* *Were the keys independent per text, or drawn from a shared pool?* *What were the floors?* *Did a live model run at every tier reported?* *Were training and evaluation material separated by source document, not just by row?* A benchmark that answers all six can be read. One that answers none cannot, whatever its headline number.

Youssef Hamdi Zafaan Ibrahim and Mohammed Khalaf Salama, [“ACTS: A multi-tier benchmark evaluating LLM cipher identification under controlled blind conditions” (arXiv:2609.26893, 22 September 2026)](<https://arxiv.org/abs/2609.26893>), abstract and tier description. Xiwen Ren, Min Luo, Cong Peng and Debiao He, [“Plaintext Structure Vulnerability: Robust Cipher Identification via a Distributional Randomness Fingerprint Feature Extractor” (arXiv:2511.08296)](<https://arxiv.org/abs/2511.08296>), abstract. Micaella Bruton, Meriem Beloucif and Beáta Megyesi, [“Attention-Augmented LSTMs for Automatic Homophonic Ciphertext Decipherment” (arXiv:2606.05078, 3 June 2026)](<https://arxiv.org/abs/2606.05078>), abstract. These are preprints, not settled general results. Classification accuracy is not plaintext recovery, and neither is a break of a modern primitive. Compare the museum’s bounded CipherBank note on the [Cipher Corpus](<https://ciphermuseum.com/cipher-corpus.html>) page.

  function countFreqs(text){
    var counts = new Array(26).fill(0);
    var total = 0;
    for(var i=0;i<text.length;i++){
      var c = text.charCodeAt(i);
      if(c>=65&&c<=90){ counts[c-65]++; total++; }
      else if(c>=97&&c<=122){ counts[c-97]++; total++; }
    }
    return {counts:counts, total:total};
  }

  function calcIC(counts, total){
    if(total<2) return 0;
    var sum=0;
    for(var i=0;i<26;i++) sum += counts[i]*(counts[i]-1);
    return sum / (total*(total-1));
  }

    var maxF = Math.max.apply(null, freqs) || 1;
    container.innerHTML = '';
    labels.innerHTML = '';
    for(var i=0;i<26;i++){
      var pct = (freqs[i]/maxF*100)||0;
      var bar = document.createElement('div');
      bar.className = 'freq-bar';
      bar.style.height = Math.max(pct,1) + '%';
      bar.setAttribute('data-pct', freqs[i].toFixed(1));

      lbl.textContent = A[i];

Shannon's Framework

#### Confusion & Diffusion

[Inline SVG: original diagram/icon markup]

```html
<svg class="icon" width="17" height="17"><use href="images/icons.svg#i-puzzle"></use></svg>
```

Confusion

Making the relationship between key and ciphertext as complex as possible. Caesar has a simple key relationship: C = P + 3. One known pair reveals the entire key.

**Modern solution:** AES S-boxes are highly non-linear. The S-box has a precise public algebraic definition. Its nonlinearity works with the other round operations; an S-box alone does not make encryption secure.

[Inline SVG: original diagram/icon markup]

```html
<svg class="icon" width="17" height="17"><use href="images/icons.svg#i-globe"></use></svg>
```

Diffusion

Spreading each plaintext bit's influence across many ciphertext bits. Caesar does not spread changes across letter positions: change one letter, change exactly one ciphertext letter.

**Modern solution:** AES combines ShiftRows and MixColumns to spread byte dependencies. Across suitable inputs, changing one bit of a full AES input changes about half the output bits on average; this is not an exact per-message promise or a standalone security proof.

The Modern Landscape

#### What Replaced Classical Cryptography

⚠️

**Taxonomy note:** Symmetric and public-key encryption schemes both reversibly transform plaintext into ciphertext. RSA encryption and RSA signatures are distinct schemes with different encoding and padding requirements. Diffie–Hellman establishes shared secrets; signatures authenticate messages; hash functions produce digests. These primitives solve different problems and must be combined with appropriate protocols.

Post-Quantum Cryptography

Sufficiently large, fault-tolerant quantum computers could break conventional RSA and Diffie–Hellman using Shor’s algorithm. NIST standardized the first three algorithms from its post-quantum project in 2024: **ML-KEM** (formerly CRYSTALS-Kyber, key encapsulation) and **ML-DSA** (formerly CRYSTALS-Dilithium, signatures), both based on structured lattice problems. NIST also standardized the hash-based SLH-DSA signature scheme in 2024. These are intended to resist known quantum attacks; they are not proofs against every future attack. The mathematics is on exhibit in the Hall of Foundations: [lattices & the SVP](<https://ciphermuseum.com/hall-of-foundations/lattices-svp.html>), [the closest-vector problem](<https://ciphermuseum.com/hall-of-foundations/closest-vector.html>), [Learning With Errors](<https://ciphermuseum.com/hall-of-foundations/learning-with-errors.html>) — an introduction to the mathematical setting of lattice-based standards — and [polynomial rings](<https://ciphermuseum.com/hall-of-foundations/polynomial-rings.html>).

Elliptic-Curve Signatures → exhibit

[ECDSA](<https://ciphermuseum.com/ciphers/ecdsa.html>) signatures verify under a public key rather than concealing content; attribution to a person requires a trusted key association: a private scalar on an elliptic curve, a public point, and a signature anyone can check. Suitable 256-bit elliptic-curve groups and 3072-bit RSA are commonly compared at roughly 128 bits of classical security, under their respective assumptions. Security requires an appropriate curve and implementation. Reused or biased nonces, side-channel leakage, faults and validation errors can compromise a signer. Shor’s algorithm also applies to the elliptic-curve discrete logarithm problem. The group law is in [the Hall of Foundations](<https://ciphermuseum.com/hall-of-foundations/elliptic-curves-real.html>).

Threshold Secret Sharing → exhibit

[Shamir’s Secret Sharing](<https://ciphermuseum.com/ciphers/shamir-secret-sharing.html>) (1979) represents the secret in a finite field and samples the remaining polynomial coefficients independently and uniformly. With distinct nonzero share coordinates, k valid shares reconstruct the secret; fewer than k preserve its prior distribution. This information-theoretic property also holds against quantum computation, but does not protect stolen shares or faulty implementations. Threshold signing protocols can build on secret-sharing ideas but require additional protections; plain Shamir sharing does not authenticate shares or perform signatures.

Zero-Knowledge Proofs → exhibit

[Zero-knowledge proofs](<https://ciphermuseum.com/ciphers/zero-knowledge-proofs.html>) combine a soundness guarantee with a specified bound on what the verifier can learn beyond the statement. The guarantee depends on the protocol and security model; toy protocols can have a visible nonzero soundness error. The succinct variants — zk-SNARKs and STARKs — validate private transactions and compress whole blocks of computation into a proof small enough to check on a blockchain. The Fiat–Shamir transformation connects certain interactive identification protocols to noninteractive proofs or signatures under additional assumptions. A signature is not automatically a general-purpose zero-knowledge proof.

#### A valid tag can belong to an old message

Suppose A carries counter 1 and B carries counter 2. Each tag covers the counter and message under the same session key. An observer records both. Compare a receiver that remembers only the last token with one that accepts a valid tag only when its counter exceeds the highest accepted counter, initially 0.

Swipe or scroll the table horizontally to see every column. Keyboard: focus the table area and use the arrow keys.

Deliver A, B, then A again; authenticate before updating state

| Delivery | Tag check | Last-token-only rule | Increasing-counter rule |
| --- | --- | --- | --- |
| A (1) | Valid | Accept | Accept; highest = 1 |
| B (2) | Valid | Accept | Accept; highest = 2 |
| A (1), replayed | Valid | Accept | Reject; highest = 2 |
| A changed to counter 3; old tag | Invalid | Reject | Reject; highest = 2 |
| Forget receiver state, keep key; replay A (1) | Valid | Accept | Accept; highest = 1 |

The A/B/A sequence defeats last-token-only checking. Resetting state under the unchanged key defeats the counter rule too. Rejected packets must not advance the accepted counter. This simplified rule rejects out-of-order messages; transports that allow reordering need a defined replay window and session lifecycle, including counter exhaustion. Replaying recorded ciphertext does not require encrypting a new message with a reused nonce: sender nonce uniqueness and receiver freshness are separate requirements.

Try the existing [Crypto Lab: Regex Veil](<https://systemslibrarian.github.io/crypto-lab-fte/>), in its **Freshness** section: open authenticated fragments twice, then reset the used-counter window. It is a local protocol teaching model, not a deployed transport.

**The museum's final lesson:** Many historical systems failed through structural weaknesses, key reuse, or operational mistakes; others are obsolete or unresolved. A correctly used one-time pad retains perfect secrecy. Modern cryptography adds computational security and public-key methods, while still depending on sound key management, and extends into protocols, signatures, and proofs.

  document.addEventListener('DOMContentLoaded', function () {
    var q = document.getElementById('q');
    var kindFilter = document.getElementById('kind-filter');
    var resultsEl = document.getElementById('results');
    var emptyEl = document.getElementById('empty');
    var statusEl = document.getElementById('status');
    var suggestionsEl = document.getElementById('suggestions');
    var indexReady = false;
    statusEl.setAttribute('role', 'status');

    function escapeHTML(s){return String(s).replace(/[&<>"']/g,function(c){return {'&':'&amp;','<':'&lt;','>':'&gt;','"':'&quot;',"'":'&#39;'}[c];});}

    function syncUrl(method) {
      var url = new URL(location.href);
      var text = q.value.trim();
      if (text) url.searchParams.set('q', text); else url.searchParams.delete('q');
      if (kindFilter.value) url.searchParams.set('kind', kindFilter.value); else url.searchParams.delete('kind');
      history[method || 'replaceState']({}, '', url.pathname + url.search + url.hash);
    }

    function render() {
      if (!indexReady) return;
      var raw = q.value.trim();
      var kind = kindFilter.value;
      if (!raw) {
        resultsEl.innerHTML = '';
        emptyEl.style.display = 'none';
        suggestionsEl.style.display = '';
        statusEl.textContent = 'Type to search · ' + (window.CipherSearch._count || '172') + ' exhibits · 13 halls · indexed pages';
        return;
      }
      suggestionsEl.style.display = 'none';
      var hits = window.CipherSearch.query(raw);
      if (kind) hits = hits.filter(function (h) { return h.entry.kind === kind; });
      var matchCount = hits.length;
      hits = hits.slice(0, 60);
      if (!hits.length) {
        resultsEl.innerHTML = '';
        emptyEl.style.display = '';
        statusEl.textContent = '0 matches for "' + raw + '"';
        return;
      }
      emptyEl.style.display = 'none';
      statusEl.textContent = matchCount + ' match' + (matchCount === 1 ? '' : 'es') + ' for "' + raw + '"' + (matchCount > hits.length ? ' · showing first ' + hits.length : '');
      var hl = window.CipherSearch.highlight;
      resultsEl.innerHTML = hits.map(function (h) {
        var e = h.entry;
        var meta = [];
        if (e.kind === 'cipher') meta.push('Cipher');
        else if (e.kind === 'hall') meta.push('Exhibit Hall');
        else meta.push('Page');
        if (e.hall && e.hall !== '—') meta.push('Hall: ' + escapeHTML(e.hall));
        if (e.created && e.created !== '—') meta.push('Created: ' + escapeHTML(e.created));
        if (e.trust) meta.push('Trust: ' + window.TrustLabels.badge(e.trust));
        var tags = e.tags.slice(0, 6).map(function (t) {
          return '<span class="sr-tag">' + escapeHTML(t) + '</span>';
        }).join('');
        return '' +
          '<a class="sr-card" href="' + escapeHTML(e.url) + '" role="listitem">' +
            '<div class="sr-head">' +
              '<h3 class="sr-title">' + hl(e.title, raw) + '</h3>' +
              '<span class="sr-kind">' + escapeHTML(e.kind) + '</span>' +
            '</div>' +
            '<div class="sr-meta">' + meta.join(' · ') + '</div>' +
            '<p class="sr-summary">' + hl(e.summary, raw) + '</p>' +
            (e.note ? '<p class="sr-summary">' + escapeHTML(e.note) + '</p>' : '') +
            (tags ? '<div class="sr-tags">' + tags + '</div>' : '') +
          '</a>';
      }).join('');
    }

    var t;
    function debounce() { clearTimeout(t); t = setTimeout(function () { render(); syncUrl('replaceState'); }, 80); }
    q.addEventListener('input', debounce);
    kindFilter.addEventListener('change', function () { render(); syncUrl('pushState'); });

    document.querySelectorAll('.suggest').forEach(function (b) {
      b.addEventListener('click', function () { q.value = b.dataset.q; render(); syncUrl('pushState'); q.focus(); });
    });

    // URL ?q= prefill
    var params = new URLSearchParams(location.search);
    var preset = params.get('q');
    var presetKind = params.get('kind');
    if (['cipher', 'hall', 'page'].indexOf(presetKind) >= 0) kindFilter.value = presetKind;

    window.addEventListener('popstate', function () {
      var state = new URLSearchParams(location.search);
      q.value = state.get('q') || '';
      var stateKind = state.get('kind') || '';
      kindFilter.value = ['cipher', 'hall', 'page'].indexOf(stateKind) >= 0 ? stateKind : '';
      render();
    });

    function init(entries) {
      var list = Array.isArray(entries) ? entries : [];
      // Count canonical exhibit identities, not descriptive kinds or utility pages.
      var exhibitCount = list.filter(function (e) { return Number.isInteger(e.exhibitNumber); }).length;
      window.CipherSearch._count = exhibitCount || '?';
      render();
    }

    function loadIndex() {
      indexReady = false;
      statusEl.textContent = 'Loading index…';
      emptyEl.style.display = 'none';
      window.CipherSearch.load().then(function (entries) {
        indexReady = true;
        init(entries);
      }).catch(function () {
        resultsEl.innerHTML = '';
        statusEl.textContent = 'The search index could not be loaded. ';
        var retry = document.createElement('button');
        retry.id = 'searchRetry'; retry.type = 'button'; retry.textContent = 'Retry';
        retry.addEventListener('click', loadIndex);
        statusEl.appendChild(retry);
      });
    }
    if (window.CipherSearch) {
      if (preset) q.value = preset;
      loadIndex();
    } else {
      statusEl.textContent = 'Search script failed to load.';
    }
  });

#### A small repeatable columnar experiment

Keep unsuccessful and preprocessing-exhausted runs in the denominator. Repeated seeds on one message are dependent; these tiny-sample counts are not general recovery probabilities. Equal score-evaluation budgets are not equal CPU time. Exact replay excludes elapsed milliseconds.

#### Engine Accuracy & Provenance

Verification evidence differs by engine. The test suite combines independently published known-answer examples, pinned outputs for explicitly educational models, roundtrip and invalid-input checks, and corpus replay. Passing a model test does not establish historical authenticity.

- Independent examples include Schneier’s Solitaire vectors, historical manual examples for RS44 and German Double Playfair, and ACA examples for AMSCO.

- Some machine and codebook demonstrations are simplified models. Their limits and source editions must be read with the exhibit.

- The v0.6 replay baseline has 99,800 exact matches and 526 documented noisy or historical-variant exceptions among 100,326 records.

- Roundtrips establish consistency, not independent correctness. The public tests distinguish their evidence types.

Where an engine follows a specific historical convention (for example, the Four-square exhibit uses the ACA 25-letter I/J-merged alphabet rather than Wikipedia's Q-omitted example), the exhibit page documents that choice. Ancient World

~1900 BC

#### Unusual Egyptian Hieroglyphs

🇪🇬 Ancient Egypt

Unusual signs in Khnumhotep II’s tomb illustrate deliberate variation in writing. Their purpose should not be equated automatically with secret encryption.

[View exhibit →](<https://ciphermuseum.com/ciphers/egyptian-substitution.html>)

~600 BC

##### Atbash

 🇮🇱 Ancient Israel

Atbash — the ancient Hebrew reflection cipher (A<->Z, B<->Y, C<->X), self-inverse and used in the Book of Jeremiah (25:26, 51:41) for SHESHACH.

 [View exhibit →](<https://ciphermuseum.com/ciphers/atbash.html>)

~500 BC

##### Scytale

 🇬🇷 Sparta

The traditional scytale reconstruction illustrates transposition, but the dates and cryptographic interpretation of ancient evidence are disputed.

 [View exhibit →](<https://ciphermuseum.com/ciphers/scytale.html>)

c. 350 BCE

##### Aeneas Tacticus — Water-Clock Signals

🇬🇷 Greece

Aeneas’s water-clock signaling, preserved in Polybius: synchronized vessels selected preset military messages, not letters of an alphabet.

[View exhibit →](<https://ciphermuseum.com/ciphers/aeneas-tacticus.html>)

c. 150 BCE

##### Polybius Square

 🇬🇷 Greece

Polybius describes coordinate signaling with the Greek alphabet arranged on five tablets. The familiar Latin I/J square is a later adaptation.

 [View exhibit →](<https://ciphermuseum.com/ciphers/polybius.html>)

1st century BCE

##### Caesar Cipher

 🇮🇹 Rome

Suetonius describes Caesar’s substitution with a shift of three. A short fixed shift can be tested exhaustively; no medieval encounter between Caesar and al-Kindi is implied.

 [View exhibit →](<https://ciphermuseum.com/ciphers/caesar.html>)

Medieval Period

~850 AD

##### Al-Kindi's Frequency Analysis

 🇮🇶 Baghdad

Al-Kindi’s surviving treatise gives an early systematic account of frequency analysis. Symbol counts can support substitution analysis, but short samples can remain ambiguous; there is no single six-century contest outcome.

~850

##### Monoalphabetic Substitution

🌍 Arabic World

A fixed substitution preserves letter counts while changing symbols. Al-Kindi’s ninth-century account is a landmark in its analysis, not the invention date of the entire family.

[View exhibit →](<https://ciphermuseum.com/ciphers/monoalphabetic.html>)

Renaissance and Early Modern

1401 Mantua example

##### Homophonic Substitution

🇮🇹 Mantua

Mantua’s surviving 1401 key illustrates multiple substitutes for plaintext letters. Such choices can flatten some counts without eliminating higher-order language patterns.

[View exhibit →](<https://ciphermuseum.com/ciphers/homophonic.html>)

c. 1404–1438

##### The Voynich Manuscript

 🌍 Central Europe

The Voynich manuscript remains undeciphered. Radiocarbon dating concerns its parchment; script, language and interpretation remain unresolved.

 [View exhibit →](<https://ciphermuseum.com/ciphers/voynich.html>)

1467

##### Alberti Cipher Disk

 🇮🇹 Italy

Alberti’s fifteenth-century cipher disk illustrates changing substitutions using two alphabets. The exhibit distinguishes historical instructions from a regular-step teaching model.

 [View exhibit →](<https://ciphermuseum.com/ciphers/alberti-disk.html>)

1553 and later variants

##### Vigenère Cipher

 🇫🇷 France

Bellaso’s 1553 work belongs to the history of polyalphabetic substitution. The familiar repeating-key shift model and its later attribution to Vigenère need to be distinguished from individual historical systems.

 [View exhibit →](<https://ciphermuseum.com/ciphers/vigenere.html>)

1563

##### Porta's Polyalphabetic

🇮🇹 Naples

Porta’s work belongs to the history of reciprocal polyalphabetic tables. Repeating-key variants can expose periodic statistical patterns; the museum specifies its own table convention.

[View exhibit →](<https://ciphermuseum.com/ciphers/porta.html>)

1586

##### The Babington Plot Cipher

 🇬🇧 England

The 1586 Babington Plot: intercepted nomenclator letters, a forged postscript, and the difference between compromised keys and an insecure transport channel.

 [View exhibit →](<https://ciphermuseum.com/ciphers/babington.html>)

1591 succession

##### The Argenti Cipher

🇮🇹 Papal States

Matteo succeeded his uncle Giovanni Battista Argenti in papal cryptographic work. Their documented methods include nomenclators, homophones and nulls; Marcello was Matteo’s younger brother.

[View exhibit →](<https://ciphermuseum.com/ciphers/argenti.html>)

1623 full description

##### Bacon's Binary Encoding

 🇬🇧 England

Bacon’s biliteral alphabet represents letters with patterns of two forms and can hide them in a carrier. Binary representation is distinct from a direct historical origin for ASCII.

 [View exhibit →](<https://ciphermuseum.com/ciphers/bacon.html>)

1640

##### Fermat's Little Theorem

🇫🇷 France

Fermat’s theorem gives aᵖ ≡ a (mod p) for integer a and prime p. It supports some primality tests, but passing a Fermat test does not prove a candidate is prime. Euler’s generalization and a prime-factor argument help explain RSA correctness.

[View exhibit →](<https://ciphermuseum.com/hall-of-foundations/euler-fermat.html>)

1643

##### John Wallis and the Civil War Ciphers

🇬🇧 England

John Wallis served successive English governments as a cryptanalyst. The interactive illustrates a nomenclator rather than reproducing an authenticated Royalist key.

[View exhibit →](<https://ciphermuseum.com/ciphers/wallis-ciphers.html>)

17th century

##### The Great Cipher of the Rossignols

 🇫🇷 France

The Rossignols’ syllabic nomenclator was deciphered by Bazeries in the 1890s. His proposed Man in the Iron Mask identification remains disputed.

 [View exhibit →](<https://ciphermuseum.com/ciphers/great-cipher.html>)

17th century tradition

##### Gronsfeld Cipher

🇩🇪 Germany

Numeric-key shifts are traditionally associated with Gronsfeld. The attribution and precise invention date are not established by the museum’s modern 0–9 model.

[View exhibit →](<https://ciphermuseum.com/ciphers/gronsfeld.html>)

c. 1760–1780 manuscript

##### Copiale Cipher

🇩🇪 Wolfenbüttel

Knight, Megyesi and Schaefer deciphered the Copiale manuscript in 2011 using transcription, statistics and manual analysis. The exhibit separates that result from its invented demonstration alphabet.

[View exhibit →](<https://ciphermuseum.com/ciphers/copiale.html>)

1763

##### Euler's Theorem & the Totient

🇷🇺 St. Petersburg

For a coprime to n, Euler’s theorem states aᵠ⁽ⁿ⁾ ≡ 1 (mod n). It helps explain RSA correctness; treating all message residues also requires the prime-factor or Chinese-remainder argument. The totient theorem alone is not a security proof.

[View exhibit →](<https://ciphermuseum.com/hall-of-foundations/euler-fermat.html>)

1779–1783

##### Culper Ring — Washington’s Spy Network

🇺🇸 New York / Long Island

Major Benjamin Tallmadge’s 1779 codebook for George Washington’s Culper Spy Ring. Roughly 760 numbered entries covering people, places, military terms, and common words — used by Abraham Woodhull and Robert Townsend on British-occupied Long Island and Manhattan.

[View exhibit →](<https://ciphermuseum.com/ciphers/culper-ring.html>)

1779–1780

##### Benedict Arnold & Major André

🇺🇸 West Point

Arnold and André used successive book references, including Blackstone and dictionary schemes. Kahn distinguishes the changing reference texts and letter-level fallback from a single fixed word-code procedure.

[View exhibit →](<https://ciphermuseum.com/ciphers/arnold-andre.html>)

1790s proposal

##### Jefferson Disk

 🇺🇸 United States

Jefferson proposed an unpublished 36-disk device. The later 25-disk M-94 illustrates a similar mechanism, but direct adoption of Jefferson’s proposal is not established.

 [View exhibit →](<https://ciphermuseum.com/ciphers/jefferson-disk.html>)

1794 documented example

##### Pigpen Cipher

🌍 Europe

Leeson’s 1794 Masonic inscription is a documented geometric-substitution example discussed by Kahn. It does not establish when every pigpen variant originated.

[View exhibit →](<https://ciphermuseum.com/ciphers/pigpen.html>)

19th and Early 20th Centuries

1817

##### Wadsworth Cipher Device

🇺🇸 United States

Wadsworth’s 1817 device uses geared disks with 33 and 26 positions. A published 2020 ciphertext-only search studied key recovery for this historical design.

[View exhibit →](<https://ciphermuseum.com/ciphers/wadsworth-cipher.html>)

1854

##### Playfair Cipher

 🇬🇧 England

Playfair cipher (1854) — Charles Wheatstone's keyed 5x5 digram cipher promoted by Lord Playfair. Used by the British in WWI; broken by digram analysis.

 [View exhibit →](<https://ciphermuseum.com/ciphers/playfair.html>)

1857

##### Beaufort Cipher

🇬🇧 United Kingdom

Beaufort cipher (1857) — Sir Francis Beaufort's reciprocal Vigenère variant where encrypt and decrypt are the same operation. Broken by Kasiski examination.

[View exhibit →](<https://ciphermuseum.com/ciphers/beaufort.html>)

~1860

##### Civil-War Dictionary Code

🇺🇸 United States · Civil War

Dictionary codes replace words with references in an agreed book. Repeated references and language patterns can still leak information; this widget is a simplified model.

[View exhibit →](<https://ciphermuseum.com/ciphers/dictionary-code.html>)

1861

##### Stager Route Cipher

🇺🇸 Union Army

The Union’s Stager system combined word transposition, code words and operational procedures. Wartime success is a historical claim, not a proof of mathematical security.

[View exhibit →](<https://ciphermuseum.com/ciphers/stager.html>)

1861–1865 use

##### Confederate Vigenère

🇺🇸 Confederate States

Confederate repeating-key traffic included the Manchester Bluff key documented in an 1863 dispatch. Union success against particular messages does not prove that three keys exposed every Confederate communication.

[View exhibit →](<https://ciphermuseum.com/ciphers/confederate-vigenere.html>)

1863

##### Kasiski Examination

 🇩🇪 Prussia

Kasiski published a repeating-key analysis method in 1863. Repeated-fragment distances suggest candidate periods, which require further checking. Babbage had investigated related attacks earlier.

1873 published scheme

##### Chinese Telegraph Code

🇨🇳 China

Viguier’s code and subsequent telegraph books represented Chinese characters numerically. A historical additive example uses digitwise modulo-ten arithmetic; the browser’s modulo-10,000 model is different.

[View exhibit →](<https://ciphermuseum.com/ciphers/chinese-telegraph.html>)

1880s attribution

##### Nihilist Cipher

🇷🇺 Imperial Russia

The additive coordinate construction is associated with Russian revolutionary cryptography. Kahn qualifies its possible inventorship; other systems also bear the Nihilist name.

[View exhibit →](<https://ciphermuseum.com/ciphers/nihilist.html>)

1885

##### The Beale Ciphers

 🇺🇸 Bedford County, Virginia

Beale ciphers — three numerical ciphers published in an 1885 Lynchburg pamphlet, said to have been written in the 1820s and to point to a Virginia treasure. The pamphlet supplies a reading for #2 using a version of the Declaration of Independence. #1 and #3 remain unresolved; the readable construction does not authenticate a treasure.

 [View exhibit →](<https://ciphermuseum.com/ciphers/beale.html>)

1890s methods

##### Bazeries: Cylinder and Hand Procedures

🇫🇷 France

Bazeries worked with both a cylinder and hand methods. The linked browser exhibit uses a labelled substitution-and-reversal model, not a cylinder simulation.

[View exhibit →](<https://ciphermuseum.com/ciphers/bazeries.html>)

~1902

##### Four-Square Cipher

🇫🇷 France

Four-Square cipher (1902) — Delastelle's digram cipher using two keyed and two standard 5x5 squares. Disrupts Playfair frequencies but breaks to digrams.

[View exhibit →](<https://ciphermuseum.com/ciphers/four-square.html>)

1902 treatise

##### Bifid Cipher

🇫🇷 France

Delastelle’s posthumous 1902 treatise describes fractionation methods. Bifid separates and recombines two-dimensional coordinates over a selected period.

[View exhibit →](<https://ciphermuseum.com/ciphers/bifid.html>)

1902 treatise

##### Trifid Cipher

🇫🇷 France

Trifid extends coordinate fractionation to three dimensions. The extra coordinate does not by itself establish greater security than every two-dimensional construction.

[View exhibit →](<https://ciphermuseum.com/ciphers/trifid.html>)

World War I and Interwar

1914

##### German Double Transposition

🇩🇪 Germany · WWI

Two successive columnar transpositions: historical military use, attack conditions, and modern computerized cryptanalysis; not an unbroken cipher until 2013.

[View exhibit →](<https://ciphermuseum.com/ciphers/double-transposition.html>)

1917 precursor

##### One-Time Pad

 🇺🇸 United States

A one-time pad offers perfect secrecy with a secret, uniform, independent message-length key used once. Try ciphertext tampering to see why secrecy is not authentication.

 [View exhibit →](<https://ciphermuseum.com/ciphers/one-time-pad.html>)

1917

##### Vernam Tape Cipher

🇺🇸 AT&T

Vernam’s teleprinter system combines text with a key stream. XOR supplies perfect secrecy only when the pad is uniformly random, independent, secret, long enough and never reused.

[View exhibit →](<https://ciphermuseum.com/ciphers/vernam.html>)

1917

##### Zimmermann Telegram

🇩🇪 Germany → 🇲🇽 Mexico

The January 1917 Zimmermann Telegram: code 0075 to Washington, then re-encoded in 13040 for Mexico. Room 40’s reading helped draw the United States into WWI.

[View exhibit →](<https://ciphermuseum.com/ciphers/zimmermann.html>)

1918

##### ADFGVX Cipher

 🇩🇪 Germany · WWI

ADFGVX combined a 6×6 substitution square with columnar transposition. Painvin’s June 1918 solutions exploited particular traffic and keys, not every later message automatically.

 [View exhibit →](<https://ciphermuseum.com/ciphers/adfgvx.html>)

March 1918

##### ADFGX Cipher

🇩🇪 Germany · WWI

Germany’s ADFGX field cipher appeared in March 1918; Painvin obtained solutions in April. Its square-plus-transposition construction required continuing key recovery.

[View exhibit →](<https://ciphermuseum.com/ciphers/adfgx.html>)

1918

##### Chaocipher

🇺🇸 United States

Chaocipher (1918) — John F. Byrne's two-disk dynamic cipher. Disclosed in 2010; published known-plaintext and in-depth ciphertext-only attacks recover its keys.

[View exhibit →](<https://ciphermuseum.com/ciphers/chaocipher.html>)

1920s–1945

##### Enigma Machine

 🇩🇪 Germany

Enigma developed from commercial machines into several military systems. Marian Rejewski reconstructed the German military machine in 1932; Polish, British and Allied teams continued the work against changing procedures and keys.

 [View exhibit →](<https://ciphermuseum.com/ciphers/enigma.html>)

1922

##### M-94 Cylinder Cipher Device

🇺🇸 US Army

The M-94, adopted by the US Army in 1922, used 25 alphabet disks. It resembles Jefferson’s earlier unpublished wheel but was independently developed.

[View exhibit →](<https://ciphermuseum.com/ciphers/m-94.html>)

1926

##### KRYHA Machine

🇩🇪🇺🇸 Germany / US commercial

Kryha’s clockwork cipher devices used irregularly moving alphabets. Friedman and colleagues attacked a published challenge in 1933; this widget uses generated settings.

[View exhibit →](<https://ciphermuseum.com/ciphers/kryha.html>)

1929

##### Hill Cipher

🇺🇸 United States

Hill’s 1929 cipher mixes groups of letters using an invertible matrix modulo 26. Suitable matched plaintext blocks can expose the key by linear algebra.

[View exhibit →](<https://ciphermuseum.com/ciphers/hill.html>)

World War II

1940

##### Siemens Geheimschreiber T52

🇩🇪 Germany

Beurling’s 1940 analysis of intercepted Siemens traffic preceded the establishment of FRA. T52 variants differ in stepping and circuitry; irregular stepping should not be assigned to every version.

[View exhibit →](<https://ciphermuseum.com/ciphers/geheimschreiber.html>)

1940s

##### Lorenz Cipher & Colossus

 🇩🇪🇬🇧 Germany / UK

Lorenz SZ40/42: Tiltman recovered messages and key from a 1941 depth; Tutte and the Research Section inferred the structure by early 1942; Colossus accelerated wheel-setting from February 1944.

 [View exhibit →](<https://ciphermuseum.com/ciphers/lorenz.html>)

1940 reconstruction

##### Purple Broken on September 20

 🇺🇸 Washington · Signal Intelligence Service

Genevieve Grotjan’s September 1940 insight contributed to the US Army SIS team’s reconstruction of PURPLE. Its six/twenty switching groups were not simply vowels versus consonants.

 [View exhibit →](<https://ciphermuseum.com/ciphers/purple.html>)

1942

##### Hagelin M-209

🇺🇸 US Army

M-209 US production begins in 1942, following 1940 trials — the US Army's portable Hagelin C-38 with six co-prime pin-wheels and a 27-bar lug cage. Broken in the field in WWII.

[View exhibit →](<https://ciphermuseum.com/ciphers/m209.html>)

1942–1945

##### Navajo Code Talkers

 🇺🇸 Pacific Theater

Navajo code talkers used a specialized military vocabulary and spelling alphabet during World War II. Their language and the constructed code were distinct layers.

 [View exhibit →](<https://ciphermuseum.com/ciphers/navajo-code-talkers.html>)

1943–1980

##### VENONA Project

🇺🇸 Arlington Hall / NSA

VENONA analysed intercepted Soviet messages, chiefly from the 1940s, by exploiting duplicated pad material. The project ran from 1943 to 1980.

[View exhibit →](<https://ciphermuseum.com/ciphers/venona.html>)

Modern Cryptography

1949

##### Shannon's Secrecy Theory

 🇺🇸 United States

Claude Shannon publishes *"Communication Theory of Secrecy Systems"* (classified 1945, published 1949) — the mathematical foundation of modern cryptography. He formalizes perfect secrecy, including the correctly used one-time pad, and describes confusion and diffusion as cipher-design principles.

1952

##### KL-7 ADONIS

🇺🇸 NSA / NATO

KL-7: an American eight-rotor cipher machine with irregular stepping and re-entry. Stolen key material compromised traffic during the Walker espionage case.

[View exhibit →](<https://ciphermuseum.com/ciphers/kl-7.html>)

1953 message / 1957 recovery

##### VIC Cipher

🇷🇺 Soviet Union

Information from Häyhänen’s defection enabled the Hollow Nickel message recovery in 1957. The linked exhibit separates historical VIC procedures from a simplified browser model.

[View exhibit →](<https://ciphermuseum.com/ciphers/vic.html>)

1956

##### Fialka M-125

🇷🇺 Soviet Union / Warsaw Pact

Fialka was a Soviet ten-rotor machine with variant-specific alphabets, stepping and a punched-card permutation. The browser uses a simplified Latin-alphabet model.

[View exhibit →](<https://ciphermuseum.com/ciphers/fialka.html>)

Historical letter-pad system · dates unverified

##### Diana Cryptosystem

Trigraph lookup convention

A public trigraph table can be used with private, one-use pad letters. The table itself is not the secret pad; the exhibit demonstrates the modulo-26 relation without establishing deployment dates.

[View exhibit →](<https://ciphermuseum.com/ciphers/diana-cryptosystem.html>)

1965 POW use

##### Tap Code

🇺🇸 Adopted by POWs in Korea, Vietnam

US prisoners in Vietnam used a 5×5 tap-code convention, communicating row and column counts through knocks. This documented use does not date the origin of every coordinate tapping system.

[View exhibit →](<https://ciphermuseum.com/ciphers/tap-code.html>)

1969 / Solved 2020

##### Zodiac Z-340 Cipher

 🇺🇸 San Francisco

Z408 was solved by the Hardens in 1969. Z340 combines homophonic substitution with transposition and exceptions; Oranchak, Blake and Van Eycke announced its solution in 2020.

 [View exhibit →](<https://ciphermuseum.com/ciphers/zodiac.html>)

1976

##### Diffie-Hellman Key Exchange

 🇺🇸 United States

Diffie and Hellman published New Directions in Cryptography in 1976. Their key-agreement construction and public-key vision transformed public research. GCHQ’s earlier classified work had distinct contributions by Ellis, Cocks and Williamson; authentication remains a separate protocol requirement.

1977

##### RSA & DES

 🇺🇸 United States

RSA was publicly introduced in 1977, and NBS standardised DES that year. Public-key encryption, signatures and symmetric block encryption serve different purposes. Cocks’s related classified proposal at GCHQ preceded public RSA research.

1980s popularisation

##### ROT13 on Usenet

🌐 Usenet

ROT13 became popular on Usenet as a spoiler obscurer in the 1980s. It is the self-inverse Caesar shift of 13. One operation toggles text in and out.

[View exhibit →](<https://ciphermuseum.com/ciphers/rot13.html>)

1990

##### Kryptos at CIA Headquarters

 🇺🇸 Langley, Virginia

Kryptos: K1–K3 publicly solved; K4 plaintext recovered from an archive in 2025, without a publicly demonstrated cryptanalytic solution.

 [View exhibit →](<https://ciphermuseum.com/ciphers/kryptos.html>)

1994

##### Shor's Algorithm

🇺🇸 Bell Labs

Peter Shor gives polynomial-time quantum algorithms for factoring and discrete logarithms. A sufficiently large, fault-tolerant quantum computer could defeat RSA and conventional Diffie–Hellman and elliptic-curve systems. Post-quantum alternatives include lattice-based ML-KEM and ML-DSA and hash-based SLH-DSA, standardized in 2024.

[View exhibit →](<https://ciphermuseum.com/hall-of-foundations/lattices-svp.html>)

1999

##### Solitaire / Pontifex

🇺🇸 Schneier

Solitaire / Pontifex (1999) — Bruce Schneier's hand cipher driven by a 54-card deck (written for Cryptonomicon). Crowley reported adjacent repeated output letters at about 1/22.5 rather than the 1/26 uniform expectation.

[View exhibit →](<https://ciphermuseum.com/ciphers/solitaire.html>)

2001

##### AES Standardized

 🇧🇪 Belgium / 🇺🇸 NIST

NIST began the AES selection process in 1997, selected Rijndael in October 2000 and published FIPS 197 in November 2001. The standard and the selection announcement are distinct milestones.

2005

##### SHA-1 Collision Attack

 🇨🇳 China

Xiaoyun Wang and team demonstrate theoretical collision attacks against SHA-1, beginning the transition to SHA-256 and SHA-3. A practical collision was demonstrated by the CWI and Google SHAttered team in 2017.

2005

##### Learning With Errors

🇮🇱 Tel Aviv University

Oded Regev introduces Learning With Errors: noisy modular equations hide a secret vector. His result connects suitable LWE parameters to worst-case lattice problems through a quantum reduction. Hardness depends on parameters; noise is not sufficient by itself. The later ML-KEM and ML-DSA standards use structured module problems, with additional assumptions for signatures.

[View exhibit →](<https://ciphermuseum.com/hall-of-foundations/learning-with-errors.html>)

2013

##### Snowden Revelations

 🌍 Global

The 2013 disclosures intensified public debate about surveillance and communications security. HTTPS protects a connection to its TLS endpoint; it is not the same as end-to-end encryption between messaging users.

Post-Quantum Standardisation

2016–2024

##### Post-Quantum Cryptography

 🌍 Global · NIST

NIST launches the Post-Quantum Cryptography project in 2016. In 2024, ML-KEM (FIPS 203), ML-DSA (FIPS 204), and SLH-DSA (FIPS 205) are standardized — intended to resist known classical and quantum attacks, under their respective assumptions.

Undated Origins and Teaching Models

Date undocumented

##### Rail Fence Cipher

🌍 Origins undocumented

Rail Fence transposes a message along a zigzag route. Rail count, offset conventions and message length define the search; there is no universal ten-rail maximum.

[View exhibit →](<https://ciphermuseum.com/ciphers/rail-fence.html>)

Historical attribution unverified

##### Geʿez Context and a Teaching Model

🇪🇹 Ethiopian Highlands

The interactive uses a modern Latin-letter substitution. No identified manuscript authenticates it as a particular Geʿez monastic cipher.

[View exhibit →](<https://ciphermuseum.com/ciphers/amharic-ge-ez-ciphers.html>)

(function(){
  var LS_PREFIX = 'ciphermuseum.tours.';

  /* Parse ?tour=mathematics from URL */
  var params = new URLSearchParams(location.search);
  var tourId = params.get('tour') || 'mathematics';
  /* Whitelist valid tour IDs */
  var VALID_TOURS = ['mathematics','wartime','hacker','unsolved-culture','foundations'];
  if(VALID_TOURS.indexOf(tourId) === -1) tourId = 'mathematics';

  var currentStop = 0;
  var tourData = null;
  var sessionVisited = null;

  function getVisited(){
    if(sessionVisited !== null) return sessionVisited.slice();
    try{
      var saved = JSON.parse(localStorage.getItem(LS_PREFIX + tourId + '.visited'));
      if(!Array.isArray(saved)) return [];
      return saved.filter(function(idx, i){
        return Number.isInteger(idx) && idx >= 0 && idx < tourData.stops.length && saved.indexOf(idx) === i;
      });
    } catch(e){ return []; }
  }
  function markVisited(idx){
    var arr = getVisited();
    if(arr.indexOf(idx)===-1) arr.push(idx);
    sessionVisited = arr;
    try{ localStorage.setItem(LS_PREFIX+tourId+'.visited', JSON.stringify(arr)); }
    catch(e){ /* Continue the tour with progress held for this page. */ }
  }

  function render(){
    if(!tourData) return;
    var stops = tourData.stops;
    var visited = getVisited();

    /* Header */
    document.getElementById('tourSub').textContent = 'Guided Tour · ' + tourData.icon;
    document.getElementById('tourTitle').textContent = tourData.title;
    document.getElementById('tourIntro').textContent = tourData.description;
    document.title = tourData.title + ' — The Cipher Museum';

    /* Sidebar list */
    var list = document.getElementById('stopList');
    list.innerHTML = '';
    stops.forEach(function(s, i){
      var li = document.createElement('li');
      li.textContent = s.label;
      if(i === currentStop) li.className = 'active';
      else if(visited.indexOf(i) !== -1) li.className = 'visited';
      li.addEventListener('click', function(){ currentStop = i; render(); });
      list.appendChild(li);
    });

    /* Main card */
    var stop = stops[currentStop];
    markVisited(currentStop);
    document.getElementById('tourCard').innerHTML =
      '<div class="tour-stop-num">Stop ' + (currentStop+1) + ' of ' + stops.length + '</div>' +
      '<h2 class="tour-stop-title">' + escapeHTML(stop.label) + '</h2>' +
