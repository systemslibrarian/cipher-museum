### Morse Code Telegraphy's universal alphabet · 1840s

Strictly speaking, Morse is not a cipher — it is the encoding that nineteenth and twentieth-century ciphers were carried on top of.

Encoding, not encryption

OriginSamuel F. B. Morse & Alfred Vail, USA

Washington–Baltimore demonstration1844 — "What hath God wrought"

International standard1865 (Paris)

Carrier forVigenère, fractionated Morse, OTP, JN-25, …

Modern roleAviation idents, amateur radio, accessibility

#### Why This Matters

Morse and Vail’s telegraph system helped make rapid long-distance electrical communication practical. International Morse, which differs from early American Morse, was standardised in the nineteenth century. Morse is a public encoding of symbols, not an encryption algorithm.

Encrypted messages travelled over several kinds of communications systems. American Civil War telegraphy used wires, not radio; later military traffic used radio, cables, teleprinters and other media. Morse could carry ciphertext, but was not the transport for almost every important cipher.

How It Works

Each letter, digit, and punctuation mark is assigned a unique sequence of dots and dashes. Within a character, elements are separated by one short gap; between characters by a longer gap; between words by a still longer gap (this demo uses `/` for the word break).

```text
SOS   = ... --- ...
HELLO = .... . .-.. .-.. ---
73    = --... ...--   (amateur-radio sign-off, "best regards")
```

The code is roughly optimised for English letter frequencies — E is a single dot, T is a single dash, common letters are short, rare letters long. This makes Morse one of the earliest examples of variable-length coding, predating Huffman by a century.

How It Was Broken

It was never "broken" — it is a public encoding

Complexity: Trivial (look up the table)

Morse is not, and was never intended to be, a cipher. It is a public encoding designed for transmission efficiency and readability. The cryptographic question is always about the cipher running on top of Morse, not Morse itself.

Operator-fingerprinting

Used for traffic analysis throughout WWII

An operator’s characteristic sending rhythm, or *fist*, can contribute to traffic analysis alongside call signs, schedules and direction finding. Such observations can suggest continuity between transmissions without decrypting their contents; a rhythm alone does not guarantee unique identification.

Voyager Golden Record Sidebar

A public encoding specifies how symbols are represented. That role differs from secrecy: knowing Morse, ASCII or a file format should not require a secret key. Encryption may be applied to content before it is encoded for a particular channel.

Morse + Cipher Combination Pattern

One possible encrypted transmission stack is:

- Encrypt plaintext with a cipher (Vigenere, transposition, OTP, etc.).

- Convert resulting ciphertext to Morse/Baudot for transmission.

- Defender receives symbols, then decrypts upstream.

This layering principle still defines modern protocol stacks: transport encoding and cryptographic secrecy are separate layers.

#### Why This Matters

Most [columnar transposition](<https://ciphermuseum.com/ciphers/columnar.html>) implementations break ties between repeated key letters from left to right. Myszkowski assigns those letters the same rank. That one change turns a set of separate columns into a group read across each row, making repeated letters part of the permutation instead of an inconvenience to resolve.

```html

```

Historical Context

Myszkowski published *Cryptographie indéchiffrable* in Paris in 1902. The title’s claim of indecipherability did not make the system secure. The exhibit follows the repeated-rank convention documented by the American Cryptogram Association: write the message by rows; read single columns downward and tied columns together across rows.

Like other hand transpositions, the method changes positions rather than letter identities. It offers a compact lesson in how a key and an exact tie rule determine a reversible permutation.

[Inline SVG: original diagram/icon markup]

```html
<svg class="icon" width="17" height="17"><use href="../images/icons.svg#i-gear"></use></svg>
```

How It Works

Sort the distinct letters of the keyword alphabetically and number them. Every occurrence of the same letter receives the same rank. With `TOMATO`, A = 1, M = 2, O = 3, and T = 4, giving `4 3 2 1 4 3`.

Write the message in rows six letters wide. Read rank 1 down its column, then rank 2. For rank 3, read both O columns from left to right in each row before going to the next row. Do the same for the two T columns at rank 4. Skip missing cells in an incomplete final row.

```text
Key:     T O M A T O
Ranks:   4 3 2 1 4 3
         W E A R E D
         I S C O V E
         R E D F L E
         E A T O N C
         E

Rank 1: ROFO
Rank 2: ACDT
Rank 3: EDSEEEAC
Rank 4: WEIVRLENE
Output: ROFOACDTEDSEEEACWEIVRLENE
```

To decrypt, construct the same occupied cells from the ciphertext length and keyword width. Fill them in rank order using the same tie rule, then read the restored grid by rows. This demo does not add padding, including when the final row is short.

Compare Columnar Transposition

For ordinary columnar transposition, repeated letters usually receive separate positions; TOMATO would have ranks `5 3 2 1 6 4`. Myszkowski’s ranks are `4 3 2 1 4 3`. The difference is visible in the demo’s grid header.

With a keyword containing no repeated letters, the two routes agree under the same no-padding convention. Try ZEBRA here and in [Columnar Transposition](<https://ciphermuseum.com/ciphers/columnar.html>) to study how a tie rule changes the cipher rather than the underlying message.

How It Can Be Broken

The cipher preserves single-letter frequencies. A suspected keyword width gives a candidate grid shape; probable words and neighbouring-letter scores constrain which positions should become adjacent. Dictionary searches can try likely keywords, while broader searches can score candidate rank patterns directly. A keyword that is easy to remember may also be easy to guess.

This is a broken classical transposition method for study and puzzles. Neither repeated ranks nor the 1902 book’s title provide modern confidentiality. It supplies no integrity check: rearranging the ciphertext can also rearrange the recovered text.

What Is Actually True

 Historical Context

This exhibit honors the Navajo Marines who served as Code Talkers during World War II. The National Archives estimates their number at 375–420. Their work depended on a designed military code, memorisation and communication skills; it remained classified until 1968.

Philip Johnston proposed using Navajo for Marine Corps communications in 1942. The programme developed a specialised code; ordinary fluency in Navajo alone was not equivalent to knowing all its military meanings.

Some of the original 29 code developers served in the later stages of the Guadalcanal campaign in 1942; the original training group should not be equated with a single deployment. The Navajo Nation’s historical account quotes Major Howard Connor, 5th Marine Division signal officer at Iwo Jima: *"Were it not for the Navajos, the Marines would never have taken Iwo Jima."*

The programme was declassified in 1968. In 2001 the original 29 recruits were honoured with Congressional Gold Medals; later Navajo Code Talkers received silver medals.

 Wartime Performance and Limits

🛡️

No successful Japanese cryptanalytic break is established in the cited wartime record. That is a historical operational result, not proof of mathematical secrecy.

Historical Context

NEMA, short for *NEue MAschine* (“new machine”), replaced the Swiss Army’s commercial Enigma K after its traffic had proved vulnerable. Development began during WWII; the Swiss Army issued NEMA operating instructions dated 30 April 1947. Zellweger manufactured the machine in Uster. Training and war-reserve versions used different stepping wheels; diplomatic machines were another variant.

The 1947 date identifies the postwar machine, rather than its wartime design work. The military configuration in this exhibit is deliberately fixed so that visitors can follow every wheel position.

[Inline SVG: original diagram/icon markup]

```html
<svg class="icon" width="17" height="17"><use href="../images/icons.svg#i-gear"></use></svg>
```

How It Works

Current enters a static entry wheel, passes through four cipher rotors, reaches a rotating reflector, and returns through the rotors in reverse. There is no plugboard. The reflector makes the operation reciprocal: reset to the same key and run the ciphertext to recover the plaintext.

Each cipher wheel has a separate mechanical stepping wheel. Notches determine which neighbouring wheels can move, and a second track on the red drive wheel gates a slower transmission. Decisions are made from the old positions; eligible wheels then step backwards before the letter is transformed. The reflector can step too.

```text
Fixed wheels (left → right): A/12  B/13  C/14  D/15
Red wheel: 22/1
Start windows: MQQPZQSOEV
Input:  AAAAAAAAAAAAAAAAAAAAAAAAAAA
Output: HRSBVOOTZUCRWLMGRMGVWYWOVNF
```

This example is checked against the published rmsk2 NEMA test, whose reference ciphertext came from Geoff Sullivan’s simulator. Decryption must start at `MQQPZQSOEV`, not at the final windows printed by the demo.

Security and Cryptanalytic Limits

The military mechanism has a maximum state period of 17,576 keypresses. A reflector also prevents a letter from encrypting to itself. Those structures constrain a cryptanalyst’s search even though the number of possible initial settings is much larger than the period.

This exhibit does not assert a documented operational break of Swiss NEMA traffic. It presents an obsolete machine and makes no claim of modern security. A message, key schedule, and operating procedure must be evaluated together.

#### Authentication is only one step

The 2026 “BREAKMEIFYOUCAN!” study examines MIFARE Ultralight C, Ultralight AES, NTAG 223/224 DNA and several compatible or counterfeit products. Its central lesson is that protocol state, writable key storage, integrity checks, key diversification and hardware quality can determine the outcome even when a device uses 3DES or AES.

This is a deployment and protocol case, not a break of the AES primitive. The tag model and configuration matter: results from one counterfeit family do not automatically apply to genuine NXP silicon or every installation.

**Hardware evidence limit:** in §14 the authors report obtaining a few NTAG 223 DNA StatusDetect samples but **no NTAG 224 DNA samples**. Their NTAG 224 DNA interpretations are preliminary, based on documentation and similarities to tested products; they are not measurements on that model.

#### The relay leaves the tag authenticated

In the paper’s relay scenario, the attacker’s goal is to leave the **tag** in an authenticated state. The legitimate reader may time out while the tag accepts the relayed exchange. That is more specific than the usual story of persuading a reader that a distant card is nearby.

Subsequent actions depend on the tag’s access controls and command integrity. Where authenticated key storage remains writable, partial overwrites can reduce the unknown key material. Multiple tags sharing a key can make recovery easier. These conditions belong next to the result; “uses AES” alone does not describe the system.

#### Configuration changes the attack surface

|  Condition to inspect |  Why it matters |
| --- | --- |
|  Locked versus writable key/configuration pages |  Controls whether the relevant post-authentication overwrite path is available. |
|  Command integrity, including enforced CMAC where supported |  Enforced Ultralight AES CMAC protects against unauthorized command injection. The paper separately describes relayed tearing of genuine WRITE commands, conditional on reader timing and the relevant writable storage; CMAC does not make these distinct attack paths equivalent. |
|  Shared versus diversified keys |  Several tags using the same secret can support attacks that are unavailable in that form with per-tag keys. Diversification does not prove every other path safe. |
|  Genuine versus compatible/counterfeit hardware |  Randomness, lock behavior and implementation details differ. Fast results on weak counterfeit generators are separate from genuine-tag results. |
|  Relay timing and authenticated state |  A reader timeout does not by itself demonstrate that the tag returned to an unauthenticated state. |

#### Demonstration, extrapolation and theory

The paper distinguishes implemented attacks from workload estimates and theoretical proposals. In particular, its single-tag Ultralight C proposal in §17 is theoretical. It requires unlocked key pages and access to a legitimate reader. The first 28-bit segment alone is estimated to require about 777 days at two reader-assisted attempts per second; further recovery stages follow. The assumed number of EEPROM writes also exceeds the guaranteed endurance, and the paper’s five-million-write experiment does not demonstrate completion of that first stage. It must not be presented as the fast counterfeit-tag demonstration.

This exhibit follows revision 1.1, dated 28 August 2026. The revision corrects an earlier recovered-bit extrapolation. Numbers copied from an older summary can therefore misrepresent the paper’s current evidence.

A browser demonstration cannot measure physical distance securely. Crypto Lab’s distance-bounding work is a related protocol lesson; this museum exhibit supplies the device history and the distinctions between authentication, proximity, integrity and key storage.

#### Why This Matters

Nomenclators combined a substitution alphabet with entries for words, names or phrases. They were widely used in European diplomacy over several centuries, but did not form one uniform system used by every court or every famous correspondent. Individual keys must be examined to distinguish substitution, syllabic codes and larger codebooks.

Historical Context

Kahn describes Gabrieli di Lavinde’s 1379 collection of keys combining letter substitutions with short word and name lists. Mantua’s 1401 key is a distinct landmark in Western homophonic substitution, not the beginning of nomenclators. Later diplomatic keys varied greatly in size and structure; Black Chambers reconstructed some of them from traffic and context.

How It Works

A teaching example can combine three parts: **(1)** a substitution alphabet mapping each letter to one or more cipher symbols (often digits 01–99), **(2)** a vocabulary list of perhaps 1,500 common words and names mapped to higher numbers, and **(3)** a list of *nulls* — symbols that mean ‘ignore me’ — sprinkled in to break frequency. #### Why This Matters

A null cipher hides selected letters inside a longer carrier text. Acrostics and related wordplay have a long history, but the evidence here does not establish this as the oldest named cipher or one universal ancient practice.

A carrier may select word initials, second letters or another agreed position. The often-repeated “PERSHING” example uses a different position rule from word initials, and its attribution needs independent evidence. How It Works

Pick a position rule. The simplest is *first letter of every word*:

```text
Carrier: Help Every Little Pup
Hidden : H E L P
```

The demo on this page builds carrier sentences from a dictionary of common English words and selects ones whose chosen letter matches the next character of your secret. Position keys it accepts:

- `first` — first letter of each word (default)

- `last` — last letter of each word

- `2`, `3`, … — Nth letter of each word

When no real word fits a needed letter, the demo fabricates a plausible-looking filler so the round-trip always closes. In real use a writer would simply rewrite the carrier sentence around the constraint.

Suspicion plus the right reading rule

Complexity: Trivial once you check

Once concealment is suspected, an analyst can try simple selection rules. That can expose a naive construction, but neither success nor a fixed recovery time is guaranteed for every carrier and rule.

Statistical anomaly

Complexity: Detectable on long carriers

Constructing a carrier under letter-selection constraints can produce awkward wording or other clues. Detection depends on the writer, carrier, selection rule and available comparison material. This page does not establish a universal statistical signature or a specific Bletchley censoring procedure.

What It Teaches Modern Cryptography

Null ciphers illustrate the broader idea of a covert channel: information is carried through a feature of an ordinary-looking message. Digital techniques use different mechanisms; resemblance does not establish a single historical lineage.

The defensive lesson is also unchanged. Defenders cannot watch every field of every packet, so attackers have rich choices for where to hide. Best modern practice is to assume covert channels exist and to design protocols that minimise the bandwidth available for them — not to chase every clever new carrier.

Historical Context

Frank Miller described a one-time pad system in 1882. Gilbert Vernam developed a teleprinter system in 1917 and received its patent in 1919. But it was Claude Shannon who proved in 1949 that the OTP achieves *perfect secrecy* — ciphertext reveals absolutely nothing about the plaintext to an attacker with unlimited computing power.

The VENONA project showed exactly what happens when the rules are broken: Soviet signals officers reused key pages under WWII supply pressure. Army codebreakers at Arlington Hall — work later continued under the NSA — decoded thousands of messages and identified Julius Rosenberg, Klaus Fuchs, and other Soviet agents.

How It Works

```text
Binary OTP: C = P XOR K; P = C XOR K
Letter OTP used below: C = (P + K) mod 26
                       P = (C − K) mod 26

Example:
Plain:  H  E  L  L  O  = 07 04 11 11 14
Key:    X  M  C  K  L  = 23 12 02 10 11 (illustrative pad)
Cipher: 30 16 13 21 25 mod 26 = E Q N V Z

Four requirements for perfect secrecy:
1. Key must be uniformly random and independent of the message (not pseudorandom)
2. Key must be as long as the message
3. Key must never be reused
4. Key must be kept secret

Without these assumptions, the perfect-secrecy guarantee does not follow
```

How It Was Broken

🔒

**Shannon's proof (1949):** For any ciphertext C and any possible plaintext P, P(plaintext=P | ciphertext=C) = P(plaintext=P). The ciphertext provides zero information about the plaintext. An attacker with unlimited computing power cannot improve on the best guess justified by the plaintext's prior distribution.

VENONA: Key Reuse Attack

Complexity: Moderate if pads reused

For a binary reused pad, C1 XOR C2 = P1 XOR P2: the key cancels, exposing a relation between the plaintexts. That relation may support crib-based recovery, but need not uniquely determine both messages. VENONA exploited reused Soviet decimal additive material and required codebook reconstruction and extensive analysis. It began in the US Army’s Signal Intelligence Service in 1943; NSA inherited the work later.

#### Why This Matters

In December 1801, Robert Patterson — a mathematician at the University of Pennsylvania — sent President Thomas Jefferson a cipher he believed could never be broken. Jefferson, a sophisticated cryptographer in his own right (designer of the wheel cipher in [Hall VII](<https://ciphermuseum.com/ciphers/jefferson-disk.html>)), was so impressed that he forwarded the system to Robert Livingston, the US minister to France, with an enthusiastic endorsement recorded in their correspondence.

Patterson closed the letter with a specimen in his own cipher, and a boast: "It will be absolutely impossible, even for one perfectly acquainted with the general system, ever to desypher the writing of another without his key." He put the number of possible keys at more than "ninety millions of millions".

There is no evidence Jefferson ever read it. Smithline, who solved it, puts it carefully: Jefferson "probably never cracked the enciphered portion of the letter", and no record indicates that anyone else had either. In June 2007 Lawren Smithline, a mathematician at the Center for Communications Research in Princeton, heard about the cipher letters from his neighbour Amy Speckart, who was working at *The Papers of Thomas Jefferson*; she pointed him at the Library of Congress scan. He solved it with dynamic programming over digraph frequencies. The message opens "In Congress July Fourth" and continues into the preamble to the Declaration of Independence — the document Jefferson himself had drafted.

Historical Context

Robert Patterson was professor of mathematics at the University of Pennsylvania. He and Jefferson corresponded often, and on a range of subjects including cryptography: at the time Jefferson was president of the American Philosophical Society and Patterson its vice president. Patterson's letter of 19 December 1801 is preserved in the Library of Congress's Jefferson Papers.

Secret diplomatic correspondence mattered to Jefferson. His reply documents interest in Patterson’s proposal, although that interest does not establish that its security claims were sound.

"I have thoroughly considered your cypher, and find it so much more convenient in practice than my wheel cypher, that I am proposing it to the Secretary of state for use in his office." *— Thomas Jefferson to Robert Patterson, 22 March 1802 ([Founders Online](<https://founders.archives.gov/documents/Jefferson/01-37-02-0083>))*

Jefferson was taken enough with the method to pass it on: he forwarded it to Robert Livingston, the American minister to France. Livingston went on using a nomenclator anyway. The system did not displace existing practice, and no earlier reading of the specimen is documented here. Beyond that the record is thin, and this page stops where the record does: there is no evidence that Jefferson worked the specimen and failed, and none that anyone else at his side attempted it.

How Patterson's Cipher Works

Patterson set out four requirements for a "perfect cypher": it should suit any language, be easy to memorise, be simple to perform, and be "absolutely inscrutable to all unacquainted with the particular key". His construction has three steps, and only three.

##### Step 1 — Write the message down the lines

In Patterson's words, "the first letter of the message is placed at the beginning of the first line, the second letter at the beginning of the second line, and so on, writing column after column, from left to right, till the whole is written." The text runs *downward* through the lines, column by column — Smithline likens the layout to writing in columns.

Three-row illustration for `INCONGRESSJULYFOURTH`, before adding nulls; this is not the original specimen’s layout.

line 1 I O R S Y U H

line 2 N N E J F R

line 3 C G S U O T

##### Step 2 — Cut into sections of at most nine lines

"This writing is then to be distributed into sections of not more than **nine** lines in each section, and these are to be numbered 1. 2. 3 &c." This limit belongs to the December 1801 proposal. The later April 1802 correspondence also describes a ten-letter keyword variant.

##### Step 3 — Transcribe the lines in a secret order, each behind arbitrary letters

Each section is written out "taking the lines of each section in any order at pleasure, inserting at the beginning of each line respectively any number of arbitrary or insignificant letters, not exceeding nine; & also filling up the vacant spaces at the end of the lines with like letters."

The same shuffle and the same counts are reused in *every* section — that repetition is what eventually gives the cipher away.

**The key**, again in Patterson's words, "will consist in knowing — the number of lines in each section, the order in which these are transcribed, and the number of insignificant letters at the beginning of each line." Written down it is a column of two-digit numbers: the first digit of each pair names a line, the sequence of those first digits gives the shuffle, and the second digit says how many arbitrary letters that line carries.

Patterson reckoned the number of available keys at more than "ninety millions of millions" — about 9 × 10<sup>13</sup>. This is Patterson’s historical estimate, not a measured attack cost or a count of the museum widget’s effective keys.

The 206-Year Decipherment Timeline

December 19, 1801

Patterson sends Jefferson the cipher proposal with a specimen ciphertext. The proposal includes a worked example and a challenge.

22 March 1802

Jefferson replies: he has "thoroughly considered your cypher", finds it "so much more convenient in practice than my wheel cypher", and is proposing it to the Secretary of State for use in his office. He subsequently forwards a version to Robert Livingston, minister to France.

April 1802

The correspondence on the cipher continues — a Jefferson document on Patterson's cipher dated 12 April and a Patterson reply of 24 April both survive. Nothing in the record shows the specimen being solved.

Afterwards

Livingston went on using a nomenclator regardless. In 1979 Ralph E. Weber described Patterson's method in *United States Diplomatic Codes and Ciphers 1775–1938* but dealt only with the worked example, skipping the challenge cipher entirely. No record indicates anyone decrypted it.

June 2007

**Lawren Smithline**, a mathematician at the Center for Communications Research in Princeton, hears about the cipher letters from his neighbour **Amy Speckart**, then working at *The Papers of Thomas Jefferson*: "We have a letter in cipher, and we can't read it." She sends him the Library of Congress scan. He solves it by scoring candidate alignments on digraph frequencies and searching with dynamic programming, recovering the key `13, 34, 57, 65, 22, 78, 49`.

March–April 2009

Smithline publishes *A Cipher to Thomas Jefferson* in *American Scientist* 97(2): 142–149. The article documents his 2007 solution.

Historical Context

The disc was recovered during Luigi Pernier’s excavations at Phaistos in 1908. The 45 unique signs include human figures, fish, birds, plants, ships, tools, and abstract shapes. The signs fall into 61 separated groups, often interpreted as words. Reading from the rim toward the centre is supported by overlapping impressions; neither the language nor the meaning of the divisions is established. Whether the language is Minoan, an early form of Greek, Anatolian, or something else entirely is unknown. The seals required to stamp the disc have never been found.

#### Why This Matters

The Pigpen cipher — used by Freemasons from at least the 18th century — is one of the most widely recognized symbol ciphers in history. It demonstrates that substituting symbols for letters provides no additional security over substituting other letters.

[Inline SVG: original diagram/icon markup]

```html
<svg class="icon" width="17" height="17"><use href="../images/icons.svg#i-scroll"></use></svg>
```

Historical Context

Pigpen alphabets use geometric fragments and dots as letter symbols. Kahn records a concrete Masonic example on James Leeson’s 1794 gravestone in New York. Layouts vary: an inscription needs its own alphabet convention, rather than an assumed universal Masonic key.

A secret pigpen alphabet is a monoalphabetic substitution; symbols preserve the same repetition patterns as letter substitutes. A published fixed alphabet can instead be decoded by lookup. Caesar’s restricted shift family has a much smaller keyspace than a freely permuted substitution, so the two should not be assigned identical attack difficulty.

How It Works

```text
The grid layouts:

 A │ B │ C     J │ K │ L
───┼───┼───   ───┼───┼───
 D │ E │ F     M │ N │ O   (dotted versions)
───┼───┼───   ───┼───┼───
 G │ H │ I     P │ Q │ R

S = ╲   T = ╳   U = ╱      (X shapes)
V = ╲•  W = ╳•  X = ╱•     (dotted X)
Y = ▽   Z = △              (chevrons)

The symbol for a letter is the set of grid lines
that enclose its cell — nothing more:
A = top-left cell    → line on the right, line below
E = centre cell      → all four sides: a closed box
H = bottom-middle    → left, top and right: open below
I = bottom-right     → line above, line to the left
...etc — a dot marks the second grid (J–R)

(The demo above prints single text characters as
stand-ins, because plain text has no glyphs for
most of these shapes. The diagram below shows this exhibit’s drawn variant; its S–Z assignment differs from the common four-wedges-per-X layout.)

Documented example:
- James Leeson’s Masonic gravestone, New York, 1794
```

How It Was Broken

Symbol Frequency Analysis

Complexity: Trivial

A known alphabet needs only lookup. With an unknown alphabet, frequencies, repeated words and word shapes can support a substitution attack. The most frequent symbol is not necessarily E, and short inscriptions may be ambiguous. No universal minutes-to-recovery guarantee follows from using geometric symbols.

Historical Context

Charles Wheatstone devised the Playfair cipher in 1854, and Lord Playfair championed it to British officials who were skeptical of more complicated cryptographic systems. Instead of encrypting one letter at a time, Playfair encrypts *pairs* of letters. The simple one-letter-to-one-letter frequency correspondence no longer applies; digraph and other language statistics still matter.

The British Army used Playfair operationally in the Second Boer War, and British and Commonwealth forces still used variants in both world wars for field traffic. It was fast enough for humans, stronger than earlier substitution ciphers, and compact enough for a pocket notebook.

The Three Rules

Split plaintext into digraphs. If a pair repeats a letter, insert X. If the message length is odd, pad the final letter with X.

**Rule 1 — Same Row**
Each letter shifts one position right, wrapping around.
AR → RM

**Rule 2 — Same Column**
Each letter shifts one position down, wrapping around.
MC → CE

**Rule 3 — Rectangle**
Each letter moves to the other corner of the rectangle, staying in its own row.
HI → BF

How It Was Broken

Digraph Frequency Analysis

Complexity: Moderate

Playfair changes the relationship between plaintext and ciphertext letter frequencies, but it does not erase language structure. Common English pairs like TH, HE, IN, ER, and AN still leave traces in ciphertext digraphs. Once enough traffic is collected, the key square can be reconstructed by testing candidate arrangements against those digraph statistics.

Known Plaintext Attack

Complexity: Low with sufficient known pairs

If the attacker knows even a few plaintext-ciphertext pairs, the key square begins to unravel. Each known plaintext/ciphertext digraph supplies positional constraints involving up to four distinct letters. With stereotyped openings like "DEAR SIR" or "HEADQUARTERS," an analyst may be able to propose cribs, which still need validation.

```javascript
(function(){
  function buildSquare(keyword) {
    var seen = {};
    var sq = [];
    var raw = (keyword + 'ABCDEFGHIKLMNOPQRSTUVWXYZ').toUpperCase().replace(/[^A-Z]/g, '').replace(/J/g, 'I');
    for (var i = 0; i < raw.length; i++) {
      if (!seen[raw[i]]) { seen[raw[i]] = true; sq.push(raw[i]); }
    }
    return sq.slice(0, 25);
  }

  function findPos(sq, ch) {
    ch = ch === 'J' ? 'I' : ch;
    var idx = sq.indexOf(ch);
    return idx >= 0 ? [Math.floor(idx / 5), idx % 5] : null;
  }

  function encryptPair(sq, a, b) {
    var pa = findPos(sq, a), pb = findPos(sq, b);
    if (!pa || !pb) return { out: '??', rule: 'unknown' };
    var r1 = pa[0], c1 = pa[1], r2 = pb[0], c2 = pb[1];
    if (r1 === r2) return { out: sq[r1*5+(c1+1)%5] + sq[r2*5+(c2+1)%5], rule: 'Same row — shift right' };
    if (c1 === c2) return { out: sq[((r1+1)%5)*5+c1] + sq[((r2+1)%5)*5+c2], rule: 'Same column — shift down' };
    return { out: sq[r1*5+c2] + sq[r2*5+c1], rule: 'Rectangle — swap columns' };
  }

  function decryptPair(sq, a, b) {
    var pa = findPos(sq, a), pb = findPos(sq, b);
    if (!pa || !pb) return { out: '??', rule: 'unknown' };
    var r1 = pa[0], c1 = pa[1], r2 = pb[0], c2 = pb[1];
    if (r1 === r2) return { out: sq[r1*5+(c1+4)%5] + sq[r2*5+(c2+4)%5], rule: 'Same row — shift left' };
    if (c1 === c2) return { out: sq[((r1+4)%5)*5+c1] + sq[((r2+4)%5)*5+c2], rule: 'Same column — shift up' };
    return { out: sq[r1*5+c2] + sq[r2*5+c1], rule: 'Rectangle — swap columns' };
  }

  function preparePairs(text) {
    var clean = text.toUpperCase().replace(/[^A-Z]/g, '').replace(/J/g, 'I');
    var pairs = [];
    var i = 0;
    while (i < clean.length) {
      // Filler is X, except when the letter needing a filler IS X — then Q,
      // since a same-letter digraph cannot be enciphered by Playfair rules.
      if (i + 1 >= clean.length) { pairs.push(clean[i] + (clean[i] === 'X' ? 'Q' : 'X')); i++; }
      else if (clean[i] === clean[i+1]) { pairs.push(clean[i] + (clean[i] === 'X' ? 'Q' : 'X')); i++; }
      else { pairs.push(clean[i] + clean[i+1]); i += 2; }
    }
    return pairs;
  }

  function renderGrid(containerId, sq, hlA, hlB) {
    var el = document.getElementById(containerId);
    if (!el) return;
    var html = '';
    for (var i = 0; i < 25; i++) {
      var cls = 'key-cell';
      if (hlA !== undefined && i === hlA) cls += ' hl-a';
      if (hlB !== undefined && i === hlB) cls += ' hl-b';
      var letter = sq[i] === 'I' ? 'I/J' : sq[i];
      html += '<div class="' + cls + '">' + letter + '</div>';
    }
    el.innerHTML = html;
  }

  var currentSquare = buildSquare('MONARCHY');
  var mode = 'encrypt';

  function updateAll() {
    var kw = document.getElementById('pf-keyword').value;
    currentSquare = buildSquare(kw);
    renderGrid('pf-grid', currentSquare);
    updatePair();
    updateMessage();
  }

  function updatePair() {
    var raw = document.getElementById('pf-pair-input').value.toUpperCase().replace(/[^A-Z]/g, '').replace(/J/g, 'I');
    if (raw.length < 2) {
      renderGrid('pf-grid-pair', currentSquare);
      document.getElementById('pf-pair-output').textContent = '—';
      document.getElementById('pf-pair-rule').textContent = 'Enter two letters';
      return;
    }
    var a = raw[0], b = raw[1];
    var result = encryptPair(currentSquare, a, b);
    document.getElementById('pf-pair-output').textContent = result.out;
    document.getElementById('pf-pair-rule').textContent = result.rule;
    var idxA = currentSquare.indexOf(a === 'J' ? 'I' : a);
    var idxB = currentSquare.indexOf(b === 'J' ? 'I' : b);
    renderGrid('pf-grid-pair', currentSquare, idxA, idxB);
  }

  function updateMessage() {
    var text = document.getElementById('pf-msg-input').value;
    var normalized = text.toUpperCase().replace(/[^A-Z]/g, '').replace(/J/g, 'I');
    var pairs = mode === 'encrypt' ? preparePairs(text) : (normalized.match(/.{1,2}/g) || []);
    var pairsEl = document.getElementById('pf-msg-pairs');
    var outEl = document.getElementById('pf-msg-output');
    if (mode !== 'encrypt' && normalized.length % 2) {
      pairsEl.textContent = ''; outEl.textContent = 'Ciphertext must have an even number of letters (complete pairs).'; return;
    }
    pairsEl.textContent = 'Digraphs: ' + pairs.join(' ');
    var result = [];
    var fn = mode === 'encrypt' ? encryptPair : decryptPair;
    for (var i = 0; i < pairs.length; i++) {
      var r = fn(currentSquare, pairs[i][0], pairs[i][1]);
      result.push(r.out);
    }
    outEl.textContent = result.join(' ');
  }

  window.setMode = function(m) {
    mode = m;
    var encBtn = document.getElementById('pf-mode-enc');
    var decBtn = document.getElementById('pf-mode-dec');
    var label = document.getElementById('pf-msg-label');
    if (m === 'encrypt') {
      encBtn.style.opacity = '1'; decBtn.style.opacity = '.5';
      label.textContent = 'Plaintext';
    } else {
      encBtn.style.opacity = '.5'; decBtn.style.opacity = '1';
      label.textContent = 'Ciphertext';
    }
    updateMessage();
  };

  document.getElementById('pf-keyword').addEventListener('input', updateAll);
  document.getElementById('pf-pair-input').addEventListener('input', updatePair);
  document.getElementById('pf-msg-input').addEventListener('input', updateMessage);

  updateAll();
})();
```

Historical Context

In *Histories* 10.45–47, Polybius describes a torch-signalling method devised by Cleoxenus and Democleitus and improved by him. The Greek alphabet was divided among five tablets. Two groups of torches identified the tablet and the letter within it; this was not a row signal followed after a pause by a column signal.

The grid became the foundation for numerous later ciphers — ADFGX, Bifid, Nihilist, and Trifid all build directly on Polybius's coordinate idea.

How It Works

The Porta cipher uses a 13-row tableau where each row is labeled with a pair of key letters (AB, CD, EF…). To encrypt:

- Find the row whose label contains the current key letter

- Look up the plaintext letter in that row

- The paired letter in the row is the ciphertext

Because rows are symmetric, the same operation decrypts — making it reciprocal like Beaufort.

#### Why This Matters

Purple was Japan's highest-grade diplomatic cipher from 1939 through the end of World War II. The US Signals Intelligence Service broke it without ever seeing the machine, building an analog replica from intercept traffic alone — one of the most impressive feats in the history of cryptanalysis. The intelligence stream that resulted, codenamed MAGIC, shaped American strategy in the Pacific and exposed the diplomatic moves of Tokyo, Berlin, and Rome to Washington in near real time.

[Inline SVG: original diagram/icon markup]

```html
<svg class="icon" width="17" height="17"><use href="../images/icons.svg#i-scroll"></use></svg>
```

Historical Context

Purple replaced Red for important Japanese diplomatic traffic in 1939. It used telephone-type stepping switches rather than Enigma-style rotors. Its wiring separated six electrical paths from twenty others. With the external alphabet connections, these groups need not correspond to vowels and consonants; “sixes” and “twenties” are the more precise names.

William Friedman recruited Frank Rowlett to lead the cryptanalytic attack. The team reconstructed the machine without possessing its hardware. Intercepts, repeated messages and known or inferred plaintext all helped the analysis. For 18 months they hunted patterns in stepping cycles. On the afternoon of September 20, 1940, junior cryptanalyst Genevieve Grotjan brought Rowlett a worksheet with a recurring alignment in the twenties. Within weeks, the SIS had constructed a working analog of Purple from inference alone.

💡

MAGIC revealed diplomatic instructions before Pearl Harbor, including the breakdown in negotiations. Those messages did not disclose the Pearl Harbor attack plan or its target. Reading diplomatic traffic was not the same as reading every Japanese operational order.

How It Works (Simplified)

This pedagogical demo is a simplified split-alphabet stepping model, not a faithful reconstruction of Purple’s wiring, alphabet connections or switch movement. It implements:

- Split the input alphabet into a 6-letter vowel set and a 20-letter consonant set.

- Apply a stepping permutation to each set, advanced by an internal counter.

- Re-merge the encrypted vowels and consonants into the output stream in the original positions.

- Step the switch positions according to a daily key.

The historical machine used one switch for the sixes and three in series for the twenties. The latter had designated fast, medium and slow roles and an irregular stepping rule. This is not an ordinary odometer, and the widget’s simple counter does not reproduce it.

How It Was Broken

Stepping-Switch Cycle Analysis

Complexity: Hard · Frank Rowlett, SIS · 1939–1940

Rowlett's team treated the twenties bank's stepping cycle as the leverage point. By tabulating which ciphertext letters appeared in which positions across many intercepts, they reconstructed the stepping behavior without ever observing the hardware. The sixes bank fell first — providing partial cribs that constrained the larger twenties problem.

Pattern Recognition (Grotjan's Insight)

Complexity: The single break · Genevieve Grotjan · 20 September 1940

On a worksheet aligning intercept plaintext-ciphertext pairs across repeated daily keys, Grotjan identified a recurring relationship in the twenties — an important step toward reconstructing that bank’s stepping switches. Rowlett later called it "one of the great breaks of the war."

⚠️

**Structural lesson:** The sixes/twenties separation gave analysts an important foothold. It does not follow that the effective keyspace was simply halved. Recovering Purple required a combination of traffic, repeated patterns, painstaking analysis and machine reconstruction.

Brute Force

#### Why This Matters

Red is historically important less for a single battle and more for methodology. It gave US cryptanalysts practical experience with Japanese machine traffic, stepping behavior, and class-partitioned substitution. When Purple replaced Red, those lessons dramatically shortened the time to conceptual breakthrough.

Historical Context

Before Purple, Japanese diplomatic traffic relied on a machine system now called Red (Type A). Like later Japanese designs, Red partitioned text into distinct character classes and processed them with different stepping behavior. Signals Intelligence Service teams in the United States attacked this traffic in the mid-1930s and produced substantial recovery.

That achievement was not final victory. It was reconnaissance in method space: analysts learned which statistical clues survive stepping substitution and how repeated diplomatic formats can anchor machine-state recovery even when hardware is unknown.

How It Works (Pedagogical Model)

- Clean the message to alphabetic text.

- Route vowels and consonants into separate substitution streams.

- Apply a stepping substitution table to each stream independently.

- Recombine characters in original order to form ciphertext.

This widget is a teaching model of separated character classes and changing substitution. It does not reconstruct Red’s historical mechanism: Type A used a rotating half-rotor, whereas Purple used stepping switches. The historical sixes/twenties distinction is more precise than treating these as permanently fixed vowel/consonant groups.

Why It Was Breakable

Character-Class Leakage

Complexity: Moderate to hard

Separating the sixes and twenties constrains the substitutions and leaves patterns within each group. Over large diplomatic traffic volumes, these traces provide footholds for state reconstruction and crib exploitation.

Operational Regularity

Complexity: Depends on discipline

Diplomatic templates, date headers, and repeated formal language generate recurring plaintext structure. Even partial cribs can bootstrap deeper machine analysis when combined with message metadata and traffic correlation.

Modern Security Lesson

| Red Design Choice | Modern Implication |
| --- | --- |
| Split substitution by character class | Avoid structural side channels across symbol classes |
| Deterministic stepping families | A deterministic schedule does not create fresh entropy; its security depends on the key and construction |
| Heavy dependence on operator discipline | Human process errors remain first-order security failures |
| Opaque hardware as security layer | Kerckhoffs still applies: assume adversary learns design |
